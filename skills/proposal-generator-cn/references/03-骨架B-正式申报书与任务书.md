# 骨架B：正式申报书 / 任务书

> 适用场景：通过预申报/建议书评审后进入的**正式申报书**填报阶段，以及立项批复后签订的**项目任务书/课题任务书**。典型包括：国防科技173计划与装备预研类项目的承研任务书、国防科工局项目建议书（代任务书）、国家重点研发计划项目正式申报书与项目任务书、国家自然科学基金等。
>
> 与 A 卷的关系：A 卷回答"**该不该做**"，B 卷回答"**怎么算做到**"。B 卷是**契约**——验收、拨款、追责都以它为准。
>
> 编制日期：本文件为通用骨架，不针对任何具体年度指南。

---

## 0. A 卷 vs B 卷 差异对照表

| 维度 | A 卷：项目建议书 / 立项论证材料 | B 卷：正式申报书 / 任务书 |
|---|---|---|
| **核心提问** | 该不该做？值不值得投？ | 怎么算做到？谁在什么时候交什么？ |
| **读者** | 评审专家、指南编制方、上级机关 | 项目承担单位、课题承担单位、专业机构、监理/验收组 |
| **性质** | 论证文本（说服性） | 契约文本（约束性） |
| **论证深度** | 立论、现状、方案比较、必要性与创新性 | 不多论证，直接落到任务、指标、分工、节点 |
| **技术指标** | 指标方向 + 预期水平（可有区间） | **指标条目化**：编号、数值、单位、测试条件、判定准则、验证方法、验证阶段；不得降低 |
| **研究内容** | 按技术逻辑分条 | **WBS**：任务—子任务—承研单位—负责人—起止—交付物 |
| **创新点** | 必写，是加分主项 | 通常不单列；创新相关内容转化为**考核指标与交付物** |
| **立项依据** | 长篇（15%–20%） | 通常不重复，仅在"任务来源"或"研制依据"中引述 |
| **进度** | 阶段划分 + 里程碑 | **甘特式/节点表**：节点名称、时间、交付物、交付形式、验证方式、考核方式 |
| **经费** | 概算（总量+科目+测算依据） | **预算**：科目—测算依据—年度—承担单位分解；含自筹/配套；含拨款节点 |
| **风险** | 风险分析与对策（说服性） | 风险应对纳入项目管理条款；重大调整走**变更审批**程序 |
| **知识产权** | 可用于"预期成果与效益"中提及 | **独立条款**：权属、使用、转移、标注要求、申报限制 |
| **保密** | 密级标注、非密声明 | **保密协议条款**（保密项目任务书应包括保密协议） |
| **质量** | 提及质量保证 | **质量管理条款**：技术状态管理、设计评审、工艺评审、产品评审、转阶段审查 |
| **验收** | 预期成果与考核方式 | **验收标准与交付物清单**：验收依据、验收方式、综合绩效评价结论分类 |
| **签署** | 项目负责人签字 + 单位盖章 | 多方签署：项目承担单位、课题承担单位、项目/课题负责人、专业机构、主责单位（按项目类型） |
| **格式硬约束** | 摘要 500 字等 | 系统填报字段长度限制、附件格式、无纸化申请要求 |

**对照表依据**：
- B 卷侧的"指标不得降低但需细化""主要研究内容不能减少和大幅调整，但需进一步细化""承诺的配套条件不能降低"等要求，见[科技部关于填报国家重点研发计划"ECMO系统研发"项目申报书（含预算申报书）的通知](https://www.most.gov.cn/tztg/202009/t20200916_158773.html)。
- 任务书与保密协议的关系，见《国家重点研发计划管理暂行办法》第十七条："主责单位负责立项批复，并组织专业机构与项目承担单位签订项目任务书；对于保密项目，任务书中应包括保密协议。"（[中国政府网](https://www.gov.cn/zhengce/zhengceku/202404/content_6947028.htm)）
- 技术就绪度与"里程碑"考核节点，见同办法第十八条："项目实施中，主责单位应指导专业机构严格按照任务书要求，加强技术就绪度管理、'里程碑'节点考核等，做好项目过程管理。"
- 综合绩效评价结论分类，见同办法第二十条："项目综合绩效评价结论分为通过、未通过两类。"
- 知识产权条款，见同办法第二十八条："重点专项形成的知识产权归属、使用和转移，按照国家有关法律、法规和政策执行。为了国家安全、国家利益和重大社会公共利益的需要，国家可许可他人有偿实施或者无偿实施项目形成的知识产权。项目形成的研究成果，应标注'国家重点研发计划资助'字样及项目编号。"
- 项目建议书与任务书合并申报的例外，见[国家国防科工局有关科研项目指南通知](https://kjc.ahpu.edu.cn/_t41/2025/1106/c731a258403/page.psp)："对于论证深度达到任务书要求的项目，鼓励项目建议书和任务书合并申报（模板见附件2）。"

**关于"代任务书"的特别提示**：国防科工局部分指南允许"项目建议书和任务书合并申报"，即同一份文本同时承担论证与契约两种功能。此时 B 卷的章节必须**叠加在 A 卷之上**，而不是替换——即保留立项依据与创新点，同时补齐指标条目化、WBS、节点考核、经费预算与条款部分。是否允许合并，取决于当年指南的原文明示。

## 2. 封面、密级与签署页

### ① 这一节要回答评委/管理机构什么疑问
"这份契约对谁生效？谁签字负责？材料是否合规齐备？"

进入 B 卷阶段，审查主体从"评审专家"变成"专业机构/项目管理部门"，审查重点从"内容好不好"变成"**形式完备不完善**"。国防科工局的形式审查明确将"申报材料的完整性、申报手续的完备性"列为主要目的之一。

### ② 必备要素清单
- [ ] 密级（★必填，模板封面首行即为"密级："）
- [ ] 项目/课题名称、编号（如有）
- [ ] 项目承担单位、课题承担单位、参与单位全称（与公章一致）
- [ ] 项目负责人、课题负责人（须与预申报一致）
- [ ] 研究周期（起止日期）、经费总额
- [ ] 项目负责人签字 + 日期
- [ ] 承担单位法定代表人/单位负责人签字 + 单位公章
- [ ] 课题承担单位盖章（多课题时逐项）
- [ ] 推荐单位/主管部门意见（如适用）并加盖公章
- [ ] 专业机构/主责单位签署栏（任务书时）
- [ ] 主管部门相关业务管理部门签署意见并加盖公章（国防科工局类）
- [ ] 财务主管领导签名（经费匡算/预算栏）

### ③ 可直接套用的写法
**多方签署栏设置参考**（据形式审查要求归纳）：
> 项目负责人签字：__________  日期：____
> （主）承研单位主要领导签字：__________  单位公章：____
> （主）承研单位财务主管领导签字（经费匡算/预算栏）：__________
> 有关部门（单位）业务管理部门意见：__________  公章：____  日期：____
— 依据：《国防科工局技术基础科研项目建议书形式审查内容及要求》第六条："项目建议书'经费匡算'栏须由（主）承研单位财务主管领导签名，'（主）承研单位诚信承诺'栏须由（主）承研单位主要领导签名并加盖公章，'有关部门（单位）意见'栏须由主管部门（单位）的相关业务管理部门签署意见并加盖公章。"（[原文](https://www.sastind.gov.cn/n10086167/n10086221/c10129631/content.html)）

**诚信承诺句式**（多家单位签署，与 A 卷单人承诺不同）：
> 项目牵头申报单位、课题申报单位、项目负责人及课题负责人须签署诚信承诺书……杜绝夸大不实，严禁弄虚作假。
— 依据：[上海交通大学科研院转发国家重点研发计划2026年度项目申报通知](https://keyan.sjtu.edu.cn/ky-tongzhi/20260731/6002.html)

### ④ 常见错误与扣分点
1. **签署主体漏项**。B 卷的签署方比 A 卷多（含财务负责人、多单位、专业机构），漏一个就要返工重签。
2. **项目负责人/承担单位与预申报不一致**。正式申报阶段"不允许修改的内容"明确包括：项目负责人、任务（课题）负责人；项目牵头申报单位、现有参与单位、推荐单位；所属专项、申报的指南方向；项目下设任务（课题）数（[科技部通知](https://www.most.gov.cn/tztg/202009/t20200916_158773.html)）。
3. **经费栏无财务负责人签名**——形式审查直接卡。
4. **密级与实际情况不符**，或涉密内容走互联网通道。
5. **无纸化申报材料格式错误**：申报材料中所需的附件材料，全部以电子扫描件上传。

## 3. 项目（课题）基本信息表

### ① 这一节要回答什么疑问
"这个项目是谁的、多大规模、什么定级、走哪个渠道？系统里和你交的纸面一致吗？"

### ② 必备要素清单
- [ ] 项目名称 / 项目编号 / 申报编号
- [ ] 所属计划、专项、指南方向（所属专项与指南方向不允许修改）
- [ ] 项目密级
- [ ] 项目类别（如快速扶持第一阶段/第二阶段、快速转化；173 重点项目/一般项目）
- [ ] 技术领域与研究方向（须与指南条目对应）
- [ ] 研究周期（起止年月）
- [ ] 研究经费（申请经费 / 自筹 / 合计）
- [ ] 项目承担单位、参与单位及数量
- [ ] 下设课题（任务）数与各课题名称
- [ ] 项目负责人、课题负责人基本信息
- [ ] 联系人、联系电话、邮箱、通信地址
- [ ] 申报渠道（自主申报 / 专家推荐 / 竞赛推荐优选；推荐单位名称）

### ③ 可直接套用的写法
**173 模板"申请人基本信息"表的字段**（可直接照搬表头）：
> 项目名称 | 研究期限 | 研究经费
> 项目负责人：姓名 / 性别 / 出生年月 / 民族 / 学位 / 职称 / 单位职务 / 办公电话 / 身份证号码
> 承担单位：单位名称 / 组织机构代码 / 单位性质 / 单位联系人 / 联系电话 / 主要地址 / 通信地址 / 邮政编码
> 经费概算（万元） | 研究期限（月） | 项目密级
— 来源：[国防科技173计划项目建议书模板](https://kjc.just.edu.cn/2021/0303/c9661a276660/page.htm)

**各单位经费汇总表**（列名直接取自快速扶持（第二阶段）模板）：

| 单位类别 | 单位名称 | 年度 | 申请经费（万元） |
|---|---|---|---|
| 主承研单位 | 【××大学】 | 20XX | 【××】（单位万元，只填到个位数） |
| 分承研单位 | 【××研究所】（选填） | 20XX | 【××】 |
| 总计 |  |  | 【××】 |

— 来源：[快速扶持项目（第二阶段）建议书模板](http://www.weain.mil.cn/ywdt/1266418919119282178.shtml)

**资质与渠道声明**：
> 本项目承研单位具备独立法人资格，并具备与项目密级相应的保密资质。申报渠道为【自主申报 / 专家推荐 / 竞赛推荐优选】。
— 依据：形式审查第九条；快速支持三条申报渠道见[全军武器装备采购信息网公告](http://www.weain.mil.cn/ywdt/1266418919119282178.shtml)

### ④ 常见错误与扣分点
1. **项目名称与汇总表/系统填报不一致**——形式审查第五条的硬性要求。
2. **指南方向填错或写成自拟方向**。
3. **经费数额大小写、单位（万元/元）混用**。
4. **课题数与实际不符**：项目下设课题数在正式申报阶段不允许修改。
5. **资质栏留空**：形式审查要求如实填写（主）承研单位具备的资质。
6. **限项未自查**：B 卷阶段监管方会查重；项目骨干的申报项目和改革前计划、国家科技重大专项、国家重点研发计划在研项目总数不得超过 2 个，且申报人不得因申报新项目而退出原有在研项目（[科技部通知](https://www.most.gov.cn/tztg/202009/t20200916_158773.html)；[国家科技管理信息系统公共服务平台答疑](https://fuwu.most.gov.cn/html/bszx/kjjhxm/20181218/2898.html)）。

## 4. 项目（课题）目标与任务来源

### ① 这一节要回答什么疑问
"这个任务是哪条指南要求的？合同义务的边界在哪？"

### ② 必备要素清单
- [ ] 指南方向原文引述（脱密后可引述的部分）
- [ ] 项目应覆盖的指南研究内容与考核指标（"项目应整体申报，须覆盖相应指南方向的全部研究内容和考核指标"）
- [ ] 项目总目标与课题目标（分层，不得错位）
- [ ] 项目目标与课题目标的承接关系
- [ ] 任务来源与上位计划（如"国家重点研发计划资助"标注要求）
- [ ] 与指南牵引性指标的对应关系
- [ ] 目标的完成判据

### ③ 可直接套用的写法
**目标分层模板**：
> 项目总目标：覆盖《【指南名称】》中"【方向名称】"的全部研究内容和考核指标，形成【成果形态】，使【能力项】达到【状态】。
> 课题【n】目标：承担项目总目标中的【子目标】，交付【交付物】，支撑项目指标【指标编号】的达成。

**指南覆盖性声明**（B 卷中必须有，因为验收要按此核对）：
> 本项目整体申报，覆盖指南方向"【方向名称】"的全部研究内容和考核指标，未遗漏【逐项列举】。
— 依据：'项目应整体申报，须覆盖相应指南方向的全部研究内容和考核指标'（[上海交通大学科研院转发通知](https://keyan.sjtu.edu.cn/ky-tongzhi/20260731/6002.html)；[国家科技管理信息系统公共服务平台答疑](https://fuwu.most.gov.cn/html/bszx/kjjhxm/20181218/2898.html)：'原则上项目须整体申报，覆盖该指南方向的全部考核指标，指南另有规定的除外'）

**成果标注义务**（民口项目必写）：
> 项目形成的研究成果，应标注"国家重点研发计划资助"字样及项目编号，英文标注："National Key R&D Program of China"。
— 依据：《国家重点研发计划管理暂行办法》第二十八条（[原文](https://www.gov.cn/zhengce/zhengceku/202404/content_6947028.htm)）

### ④ 常见错误与扣分点
1. **项目目标与课题目标重复**：课题目标是项目目标的分解，不是复制。
2. **未覆盖指南全部研究内容/考核指标**——形式审查和评审都会直接判定不满足要求。
3. **未标注成果资助标记要求**（民口项目）。
4. **目标用词不可判定**：B 卷一旦确立目标，验收就按字面判定。
5. **在正式申报阶段偷偷调整目标口径**：考核指标不能降低，但需进一步细化；如需增加研究内容，应提交说明作为附件。

## 5. 研究内容与工作分解结构（WBS）

### ① 这一节要回答什么疑问
"这些工作谁做、做到什么程度、彼此怎么衔接？"

### ② 必备要素清单
- [ ] WBS 层级：项目 → 课题（任务）→ 子任务 → 工作包
- [ ] 每个工作包：名称、内容、承担单位、负责人、起止时间、交付物
- [ ] 工作包之间的输入输出接口
- [ ] 关键技术在各工作包中的落点
- [ ] WBS 与指标的映射矩阵（哪个工作包产出哪项指标）
- [ ] WBS 与经费的映射（哪个工作包花多少钱）
- [ ] 与预申报书一致性声明（主要研究内容不能减少和大幅调整）

### ③ 可直接套用的写法
**WBS 表模板**：

| WBS 编号 | 工作包名称 | 主要工作内容 | 承担单位 | 负责人 | 起止时间 | 交付物 | 对应指标 |
|---|---|---|---|---|---|---|---|
| 1 | 【课题1名称】 |  | 【主承研单位】 | 【姓名】 | 【YYYY.MM–YYYY.MM】 | 【交付物】 | 【指标1、2】 |
| 1.1 | 【子任务】 |  |  |  |  |  |  |
| 2 | 【课题2名称】 |  | 【分承研单位】 |  |  |  |  |

**研究内容条目模板**（快速转化模板的写法）：
> 列出本项目研究涉及的主要研究、试验等工作内容。
> 【子任务】（1）【具体工作】；（2）【具体工作】。
— 来源：[快速转化项目建议书模板](http://www.weain.mil.cn/ywdt/1266418919119282178.shtml)

**关键技术条目模板**（快速转化模板的写法）：
> 关键技术【n】：【技术名称】——【内涵简述】。
— 同上

**一致性声明句式**：
> 本申报书研究内容与前期提交的项目预申报书保持一致；主要研究内容未减少和大幅调整，在此基础上对【子内容】进行了进一步细化。新增研究内容【××】已提交说明作为附件。
— 依据：'主要研究内容不能减少和大幅调整，但需进一步细化，如需增加研究内容，应提交说明作为附件'（[科技部通知](https://www.most.gov.cn/tztg/202009/t20200916_158773.html)）

### ④ 常见错误与扣分点
1. **WBS 只有一层**（项目→课题），无法支撑分工与经费分解。
2. **工作包无交付物**：没有交付物的工作包在验收时无法判定完成。
3. **交付物形态不明确**（"研究成果一份"无效；应写明"算法源代码及文档 1 套/原理样机 1 台/测试报告 1 份"）。
4. **分工出现空白或重叠**：同一工作包两个单位都写，或关键环节无人认领。
5. **WBS 与预申报书不一致**且未提交说明。
6. **未标注关键技术的承担单位**：关键技术必须落到具体单位，否则无法追责。

## 6. 技术方案与技术路线

### ① 这一节要回答什么疑问
"方案是否已经收敛到可执行的唯一路线？"

### ② 必备要素清单
- [ ] 总体方案与系统组成（框图）
- [ ] 分系统/分模块技术方案，与承担单位对应
- [ ] 技术路线图（含各节点技术状态）
- [ ] 关键技术的实现途径与验证方式
- [ ] 技术状态基线（B 卷阶段方案应已冻结；后续更改按变更程序走）
- [ ] 采用的成熟技术与新技术清单，及新技术的验证安排
- [ ] 拟采用的标准清单（GJB / GB / 行业标准）

### ③ 可直接套用的写法
**技术状态管理与更改控制条款**（B 卷特有，A 卷一般不需要）：
> 项目研制、生产过程严格实施技术状态管理。更改技术状态应当按照规定履行审批手续；对可能影响武器装备性能和合同要求的技术状态的更改，应充分论证和验证，并经原审批部门批准。
— 依据：《武器装备质量管理条例》第二十三条（[原文](https://www.gov.cn/zhengce/2010-10/08/content_2602566.htm)）

**新技术采用与验证条款**：
> 对设计方案采用的新技术、新材料、新工艺进行充分的论证、试验和鉴定，并按规定履行审批手续。
— 依据：同条例第二十一条

**设计/工艺/产品评审条款**：
> 严格执行设计评审、工艺评审和产品质量评审制度。对技术复杂、质量要求高的产品，进行可靠性、维修性、保障性、测试性和安全性以及计算机软件、元器件、原材料等专题评审。
— 依据：同条例第二十四条

**标准化与"三化"条款**：
> 在满足研制总要求和合同要求的前提下，优先采用成熟技术和通用化、系列化、组合化的产品。
— 依据：同条例第二十一条

### ④ 常见错误与扣分点
1. **方案尚未收敛**：B 卷里还在写"拟在 A/B 两方案间择优"——那是 A 卷的语言。B 卷方案应已定，多方案只能作为备选风险应对写入。
2. **技术路线与 WBS 不对应**。
3. **无技术状态管理表述**：军工项目任务书缺少更改审批条款，是明显的口径错误。
4. **未列采用标准**：武器装备论证、研制、生产、试验和维修应当执行军用标准以及其他满足武器装备质量要求的国家标准、行业标准和企业标准（同条例第五条）。
5. **软件类工作未写工程化管理和独立测试**：武器装备研制单位应当对计算机软件开发实施工程化管理，对影响武器装备性能和安全的计算机软件进行独立的测试和评价（同条例第二十二条）。

## 7. 技术指标的可考核化

### ① 这一节要回答什么疑问
"用哪把尺子、在什么条件下量、谁来量、量到什么算合格？"

**这是 B 卷与 A 卷最大的差异所在**。A 卷写"指标方向"，B 卷写"判决书"。

### ② 必备要素清单
- [ ] 指标条目化：编号 / 名称 / 指标值 / 单位 / 测试条件 / 判定准则
- [ ] 每项指标的**测试方法**（试验大纲、仿真条件、样本量、重复次数）
- [ ] 每项指标的**判定准则**（数值判据、合格判据、统计判据）
- [ ] 每项指标的**验证主体**（第三方测试机构 / 总体单位 / 用户单位 / 承研方自测）与资质要求
- [ ] 每项指标的**验证阶段**（在哪个节点验证）
- [ ] 指标不得降低声明 + 细化说明
- [ ] 指标变更的审批程序
- [ ] 指标与交付物的对应

### ③ 可直接套用的写法
**指标可考核化主表**：

| 指标编号 | 指标名称 | 指标值 | 单位 | 测试条件/状态 | 测试方法 | 判定准则 | 验证主体 | 验证节点 | 支撑交付物 |
|---|---|---|---|---|---|---|---|---|---|
| K1 | 【指标】 | ≥【值】 | 【单位】 | 【条件】 | 依据【试验大纲/标准号】 | 【判据】 | 【第三方/总体/自测】 | 节点【n】 | 【D1】 |

**指标细化声明**：
> 本申报书对预申报书考核指标进行了进一步细化，未降低任何指标要求。细化内容为：明确测试条件、测试方法与判定准则。
— 依据：'考核指标不能降低，但需进一步细化'（[科技部通知](https://www.most.gov.cn/tztg/202009/t20200916_158773.html)）

**考核方式模板（军味，直接取自官方模板提示语）**：
> 明确该项成果的考核方式，包括考核实施单位（具有相关测试评价资质的第三方、武器装备研制总体单位或承研方自测）、考核环境、考核方法、考核依据（标准）、考核指标等。
> 考核项目应全面覆盖所列项目关键问题、项目技术指标、项目主要成果。考核方式应与技术成熟度等级要求一致。
— 来源：[快速转化项目建议书模板](http://www.weain.mil.cn/ywdt/1266418919119282178.shtml)

**技术就绪度考核化表述**（可直接引用的政策方向）：
> 针对技术体系清晰、定量考核指标明确的相关任务方向，探索实行技术就绪度管理。申报指南中将明确技术就绪度要求，并在后续评审立项、考核评估中纳入技术就绪度指标，科学设定"里程碑"考核节点。
— 依据：[上海交通大学科研院转发国家重点研发计划"高端科研仪器研制"重点专项2026年度项目申报通知](https://keyan.sjtu.edu.cn/ky-tongzhi/20260731/6002.html)
> 项目实施中，主责单位应指导专业机构严格按照任务书要求，加强技术就绪度管理、"里程碑"节点考核等，做好项目过程管理。
— 依据：《国家重点研发计划管理暂行办法》第十八条（[原文](https://www.gov.cn/zhengce/zhengceku/202404/content_6947028.htm)）

**军工项目的指标转阶段验证**：
> 军队有关装备部门按照武器装备研制程序，组织转阶段审查，确认达到规定的质量要求后，方可批准转入下一研制阶段。
— 依据：《武器装备质量管理条例》第二十五条（[原文](https://www.gov.cn/zhengce/2010-10/08/content_2602566.htm)）

### ④ 常见错误与扣分点
1. **指标无测试条件**：B 卷最终要按字面验收，"精度优于 1 m"这种无条件的指标在验收时必然产生争议。
2. **判定准则写"达到设计要求"**——循环定义，等于没有判据。
3. **验证主体全是承研方自测**：缺少第三方或总体单位考核环节。
4. **指标与交付物脱节**：某项指标无任何交付物支撑。
5. **在正式申报阶段降低指标**：明文禁止。
6. **技术成熟度只写在文本里，没进考核表**：指南明确要求纳入技术就绪度指标与里程碑考核节点。
7. **忽视试验大纲/标准的引用**：判定依据应落到具体标准号或试验大纲编号，否则验收时无据可依。

## 8. 承研单位分工与人员安排

### ① 这一节要回答什么疑问
"哪家单位负什么责？人够不够？有没有超项？"

### ② 必备要素清单
- [ ] 牵头单位 / 参与单位清单，含法人资格与资质
- [ ] 每家单位承担的任务、负责的 WBS 编号
- [ ] 每家单位的经费额度，**各单位之和 = 项目总经费**
- [ ] 联合申报协议（明确各单位任务分工、考核指标、经费分配，项目负责人、课题负责人签字）
- [ ] 项目负责人 / 课题负责人 / 骨干成员表（含年工作量）
- [ ] 责任体系：技术负责人与行政负责人的职责划分
- [ ] 人员变更程序
- [ ] 超项自查结论

### ③ 可直接套用的写法
**人员表模板**（列名取自快速扶持（第二阶段）与快速转化模板）：

| 姓名 | 出生年月 | 职务（职称） | 单位 | 分工 | 年工作量 | 备注 |
|---|---|---|---|---|---|---|
| 【姓名】 | 【YYYY.MM】 | 【职务/职称】 | 【单位】 | 【负责WBS 1.2】 | 【X 个月/年】 |  |

— 来源：[快速扶持项目（第二阶段）建议书模板](http://www.weain.mil.cn/ywdt/1266418919119282178.shtml)

**分工与经费一致性声明**：
> 联合承研单位【名称】承担【任务】，对应 WBS【编号】；申请经费【×××】万元；各单位经费之和与项目总经费一致。
— 依据：《国防科工局技术基础科研项目建议书形式审查内容及要求》第十条（[原文](https://www.sastind.gov.cn/n10086167/n10086221/c10129631/content.html)）

**责任体系条款**（军工项目可直接引用其制度表述）：
> 项目实行技术指挥系统与行政指挥系统分工负责的责任制。
> 总设计师系统负责技术工作，总设计师是技术总负责人，即设计技术方面的组织者、指挥者、重大技术问题的决策者；行政指挥系统负责组织指挥、计划调度及人员、经费、物资保障，总指挥是行政总负责人。
— 依据：《武器装备研制设计师系统和行政指挥系统工作条例》第二条、第三条、第八条、第十三条（[原文](https://www.sastind.gov.cn/n10086167/n10086221/c10130145/content.html)）

**负责人资格与工作时间的合规声明**：
> 项目（课题）负责人具有【高级职称/博士学位】，每年用于项目的工作时间不少于 6 个月，未超过限项要求。
— 依据：'项目（含任务或课题）负责人须具有高级职称或博士学位……工作时间每年不得少于6个月'（[国家科技管理信息系统公共服务平台答疑](https://fuwu.most.gov.cn/html/bszx/kjjhxm/20181218/2898.html)）；173 计划要求负责人每年度投入项目工作时间不低于 6 个月（[南昌大学转发通知](http://kjc.ncu.edu.cn/info/1041/2231.htm)）

### ④ 常见错误与扣分点
1. **各单位经费之和 ≠ 总经费**（形式审查直接判不通过）。
2. **联合申报协议缺项目负责人/课题负责人签字**，或未明确"各单位任务分工、考核指标、经费分配"三项内容。
3. **人员表缺年工作量**：快速支持第二阶段与快速转化模板的人员表都含此列。
4. **负责人超项**且未自查：可利用国科管系统"人员查询"功能自行开展查重。
5. **新增人员造成超项**：应在已有项目（课题/任务）负责人基础上补充其他参加人员，并注意避免新增人员的超项问题。
6. **参与单位数超上限**：可根据实际情况适当增加参与单位，但参与单位总数不得突破指南规定的上限，且需要补充新的联合申报协议。
7. **参与单位资格不符**：申报书中涉及的所有参与单位都要求在中国大陆境内注册 1 年以上；中央和地方各级国家机关不得牵头或参与申报。

## 9. 进度计划与节点考核（里程碑）

"什么时候交什么？中途怎么考核？"

- [ ] 节点清单：节点编号、节点名称、时间、交付物、交付形式、验证方式、考核方式
- [ ] 里程碑与拨款挂钩关系（如适用）
- [ ] 转阶段条件
- [ ] 关键路径、外部依赖、并行/串行关系
- [ ] 节点延误的处理机制

### ③ 可直接套用的写法
**进度安排表模板**（列名直接取自快速扶持/快速转化模板的"进度安排"表）：

| 年度 | 主要完成内容和技术指标 | 完成标志 | 备注 |
|---|---|---|---|
| 20XX | 【内容】，实现【指标编号】 | 如通过测试、试车、评估等；或标志性成果 | 【外部依赖】 |

— 来源：[快速扶持项目（第二阶段）建议书模板](http://www.weain.mil.cn/ywdt/1266418919119282178.shtml)；[快速转化项目建议书模板](http://www.weain.mil.cn/ywdt/1266418919119282178.shtml)

**节点考核表模板（B 卷特有）**：

| 节点编号 | 节点名称 | 计划时间 | 交付物 | 交付形式 | 验证方式 | 考核方式 |

> 装备预研快速支持类项目：由收款单位提供加盖单位公章、财务专用章的收款凭据后，即可办理经费拨付。

— 同上公告第7、8、9条

### ④ 常见错误与扣分点
1. **节点无交付物**，或交付物写成"研究进展汇报"。
2. **节点与指标验证阶段错位**：某项指标要到最后验证，却在早期节点就列为考核内容。
3. **节点设置类别写错**：快速扶持项目"不设中间考核节点"，写了反而暴露不了解机制。
4. **甘特图无关键路径**，看不出并行性。
5. **无节点延误处理机制**：B 卷应写明节点延误的报告与调整程序。
6. **节点未与里程碑拨款对应**（若指南采用里程碑拨款方式）。

## 10. 经费预算与编制依据

### ① 这一节要回答什么疑问
"每一笔钱算出依据是什么？谁来花？哪一年花？"

**民口（国家重点研发计划）预算口径与原则**：
> 直接费用各科目预算均无比例限制，各项目（课题）应根据本技术领域的规律和特点实事求是进行测算；对于因研究任务的特色需要而预算强度较大的支出，必须进行重点说明；对于课题有多家参与单位，以课题整体为单元编制具体预算，无需编制各参与单位的具体科目预算；间接费用核定，以课题为单位，根据课题申请的专项经费额度，按规定比例核定，由项目整体汇总。
> 按照"目标相关性、政策相符性和经济合理性"的原则，科学合理、实事求是地进行编制；每个项目设定专项经费指导数，正式申报项目专项经费预算不得高于经费指导数。
— 依据：[科技部关于填报国家重点研发计划"ECMO系统研发"项目申报书（含预算申报书）的通知](https://www.most.gov.cn/tztg/202009/t20200916_158773.html)

**预算编制责任主体划分（民口）**：
> 项目和课题预算编制的责任主体分别是项目申报单位和课题牵头单位。项目申报单位负责组织各课题牵头单位以课题为单元编制预算，课题牵头单位根据课题分解情况，负责组织各参与单位共同编制本课题预算，各课题预算汇总形成项目预算。
— 同上

**预算编报的政策依据（民口，需在文本中引用文件号）**：
> 按照《国家重点研发计划重点专项项目预算编报指南》的具体要求编报预算（该指南见《科技部关于印发〈国家重点研发计划资金管理办法〉配套实施细则的通知》，国科发资〔2017〕261号）。
— 同上

**测算依据的写法模板**：
> 【科目名称】：【金额】万元。依据：【单价】元×【数量】=【金额】万元；单价来源：【标准/市场询价/历史同类项目】。

**军口经费的硬约束（可直接引用的两条）**：
> 管理费不得超过项目成本总额的 8%，子项目经费之和须与总经费一致。
— 依据：《国防科工局技术基础科研项目建议书形式审查内容及要求》第八条（[原文](https://www.sastind.gov.cn/n10086167/n10086221/c10129631/content.html)）
> 项目国拨经费不超过项目总经费的 70%。
— 依据：国家国防科工局 2025 年 10 月有关科研项目指南通知（[安徽工程大学科技处转发](https://kjc.ahpu.edu.cn/_t41/2025/1106/c731a258403/page.psp)）

**简化预算编制的适用条件（民口）**：
> 同时满足以下两个条件的单位可实行简化预算编制：一是《科技部办公厅 财政部办公厅关于进一步推动基于绩效、诚信和能力的科研管理改革试点工作的通知》（国科办政〔2019〕4号）确定的 63 家试点单位；二是其作为课题承担单位承担的国家重点研发计划课题。
— 依据：[科技部通知](https://www.most.gov.cn/tztg/202009/t20200916_158773.html)

### ④ 常见错误与扣分点
1. **科目无测算依据**：只给金额不给算法，B 卷阶段会被逐条质询。
2. **科目口径混乱**：军口项目套民口科目表，或反之。
3. **各单位/各课题经费之和与总额不符**——形式审查硬性判据。
4. **管理费超 8%**（国防科工局类项目）。
5. **国拨经费占比超 70%**（国防科工局 2025 年类项目）。
6. **预算超专项经费指导数**（国家重点研发计划明确禁止）。
7. **自筹/配套无来源证明**：明确有配套经费的项目，应出具自筹经费来源证明，并明确配套金额；承诺的配套条件不能降低。
8. **以课题为单元编制时却按单位拆分科目**（民口明确"无需编制各参与单位的具体科目预算"）。
9. **间接费用核定方式写错**：以课题为单位核定，由项目整体汇总。

## 11. 研究条件与保障措施

### ① 这一节要回答什么疑问
"资源到位了吗？谁来保障？"

### ② 必备要素清单
- [ ] 本单位研究基础（与本项目直接相关的前期工作与条件）
- [ ] 人才条件（负责人概况 + 参研人员表）
- [ ] 研究条件（场地、装置、测试能力、软件、算力、数据）
- [ ] 外协条件（外协单位名称、原因、负责内容）

- [ ] 配套条件承诺（不得低于预申报承诺）

### ③ 可直接套用的写法
**快速转化项目建议书模板规定的"研究条件及保障措施"五个二级标题**（可直接照搬结构）：
> 本单位研究基础 / 人才条件 / 研究条件 / 外协条件 / 管理保障
> 外协条件：主要列举本项目需要外协的单位名称，简要说明原因，并写清各单位所需负责内容。
— 来源：[快速转化项目建议书模板](http://www.weain.mil.cn/ywdt/1266418919119282178.shtml)

**质量管理体系声明（军工项目必备）**：
> 本单位已建立健全质量管理体系，对所承担的论证、研制、生产、试验和维修任务实行有效的质量管理；执行军用标准以及其他满足武器装备质量要求的国家标准、行业标准和企业标准。
— 依据：《武器装备质量管理条例》第四条、第五条（[原文](https://www.gov.cn/zhengce/2010-10/08/content_2602566.htm)）

**质量信息管理声明**：
> 建立武器装备质量信息系统和信息交流制度，及时记录、收集、分析、上报、反馈、交流质量信息，实现质量信息资源共享，并确保质量信息安全和保密。
— 依据：同条例第六条

**配套条件不降低声明**：
> 本项目承诺的配套条件与预申报书一致，未降低。
— 依据：'承诺的配套条件不能降低'（[科技部通知](https://www.most.gov.cn/tztg/202009/t20200916_158773.html)）

### ④ 常见错误与扣分点
1. **外协只写单位名不写内容**：模板明确要求"简要说明原因，并写清各单位所需负责内容"。
2. **无管理保障节**：B 卷的"管理保障"是契约执行的抓手，不能省。
3. **研究条件与技术要求不匹配**：声称"具备测试能力"却无对应设备清单或资质。
4. **配套条件较预申报缩水**——明文禁止。
5. **质量管理体系表述缺失**（军工项目）。

## 12. 知识产权与成果归属

### ① 这一节要回答什么疑问
"做出来的东西归谁？能不能公开？能不能转让？"

### ② 必备要素清单
- [ ] 成果界定（哪些算本项目成果）
- [ ] 权属约定（国家 / 承担单位 / 共有；军口与民口规则不同）
- [ ] 成果使用与转移的条件与审批程序
- [ ] 成果标注要求（资助标记、项目编号）
- [ ] 数据与科学数据汇交义务
- [ ] 论文/专著发表前的审查程序（涉密与敏感信息审查）
- [ ] 专利（含国防专利）申请与管理的约定
- [ ] 保密期内的权利限制
- [ ] 成果转化与利益分配机制

### ③ 可直接套用的写法
**民口知识产权条款（可直接引用）**：
> 项目形成的知识产权归属、使用和转移，按照国家有关法律、法规和政策执行。为了国家安全、国家利益和重大社会公共利益的需要，国家可许可他人有偿实施或者无偿实施项目形成的知识产权。项目形成的研究成果，应标注"国家重点研发计划资助"字样及项目编号。
— 依据：《国家重点研发计划管理暂行办法》第二十八条（[原文](https://www.gov.cn/zhengce/zhengceku/202404/content_6947028.htm)）

**军口知识产权条款（可直接引用）**：
> 国防专利是指涉及国防利益以及对国防建设具有潜在作用需要保密的发明专利。国防专利权的保护期限为 20 年，自申请日起计算。国防专利申请权和国防专利权经批准可以向国内的中国单位和个人转让……禁止向国外的单位和个人以及在国内的外国人和外国机构转让国防专利申请权和国防专利权。
— 依据：《国防专利条例》第二条、第五条、第七条、第八条（[国家知识产权局](https://www.cnipa.gov.cn/art/2015/9/8/art_98_28198.html)）

**国防专利的提交方式（可写入流程条款）**：
> 申请国防专利的，应当向国防专利机构提交请求书、说明书及其摘要和权利要求书等文件；并亲自送交或者经过机要通信以及其他保密方式传交国防专利机构，不得按普通函件邮寄。
— 依据：同条例第十条

**绝密级成果的特别限制**：
> 涉及国防利益或者对国防建设具有潜在作用被确定为绝密级国家秘密的发明不得申请国防专利。
— 依据：同条例第四条

**成果管理依据（军口相关项目）**：
> 标准化专业标准研制类项目须随附标准初稿。成果管理与推广专业成果推广类项目，须由成果持有单位与成果应用单位联合申报。
— 依据：《国防科工局技术基础科研项目建议书形式审查内容及要求》第十一条（[原文](https://www.sastind.gov.cn/n10086167/n10086221/c10129631/content.html)）

### ④ 常见错误与扣分点
1. **权属约定空白或写"另行协商"**：B 卷是契约，权属必须落定。
2. **民口项目漏写成果标注义务**。
3. **论文发表无审查程序**：涉密与敏感信息审查程序必须入条款。
4. **把国防专利当普通专利处理**：提交方式、转让限制、绝密级禁止申请等规则完全不同。
5. **数据汇交义务遗漏**：民口项目有科学数据汇交要求（"落实国家科技报告、科学数据汇交和科技成果汇交制度"，《国家重点研发计划管理暂行办法》第六条）。
6. **产学研合作的知识产权条款不完整**：可参考《产学研合作协议知识产权相关条款制定指引（试行）》（[国家知识产权局解读](https://www.cnipa.gov.cn/art/2021/10/18/art_66_170828.html)）。

## 13. 保密与质量管理条款

### ① 这一节要回答什么疑问
"保密怎么管？质量怎么控？出了问题谁负责？"

### ② 必备要素清单
- [ ] 项目密级与定密依据
- [ ] 保密协议（保密项目任务书**应包括保密协议**）
- [ ] 保密资格与人员管理要求
- [ ] 涉密载体、信息系统、外出携带的管理要求
- [ ] 宣传报道与论文发表审查程序
- [ ] 解密与变更密级程序
- [ ] 质量管理体系与质量责任制
- [ ] 技术状态管理、设计/工艺/产品质量评审制度
- [ ] 计量保障与标准化审查
- [ ] 质量信息上报与质量问题处理程序
- [ ] 科技伦理与安全审查（涉生物、信息安全等）

### ③ 可直接套用的写法
**任务书含保密协议的依据（民口可直接引用）**：
> 主责单位负责立项批复，并组织专业机构与项目承担单位签订项目任务书；对于保密项目，任务书中应包括保密协议。
— 依据：《国家重点研发计划管理暂行办法》第十七条（[原文](https://www.gov.cn/zhengce/zhengceku/202404/content_6947028.htm)）

**项目专项保密条款（民口可直接引用）**：
> 主责单位应加强重点专项的保密制度建设，完善保密工作责任体系，对涉及科技敏感信息和国家秘密的专项项目及其成果，应按有关规定执行并严格管理，分级分类做好信息安全管理，确保国家秘密安全。
— 依据：同办法第二十七条

**质量管理体系与制度条款**（军工项目，可直接引用）：
> 建立并有效运行质量管理体系；执行设计评审、工艺评审和产品质量评审制度；实行图样和技术资料的校对、审核、批准的审签制度，工艺和质量会签制度以及标准化审查制度；对关键件或关键特性、重要件或重要特性、关键工序、特种工艺编制质量控制文件。
— 依据：《武器装备质量管理条例》第四条、第二十四条、第二十六条、第二十七条（[原文](https://www.gov.cn/zhengce/2010-10/08/content_2602566.htm)）

**合同质量条款要件（军工项目）**：
> 订立武器装备研制、生产合同应当明确规定武器装备的性能指标、质量保证要求、依据的标准、验收准则和方法以及合同双方的质量责任。
— 依据：同条例第十七条

**质量保证的组织归属**：
> 武器装备研制、生产涉及若干单位的，其质量保证工作由任务总体单位或者总承包单位负责组织。
— 依据：同条例第十八条

**第三方/独立测试条款**：
> 对影响武器装备性能和安全的计算机软件进行独立的测试和评价。
— 依据：同条例第二十二条

**科技伦理与安全条款（民口必写，按项目性质选择）**：
> 涉及科技伦理与科技安全（如生物安全、信息安全等）的项目，项目（课题）负责人和参与者应加强相关知识学习，严格执行国家有关法律法规和伦理准则。
— 依据：[上海交通大学科研院转发通知](https://keyan.sjtu.edu.cn/ky-tongzhi/20260731/6002.html)

### ④ 常见错误与扣分点
1. **任务书中无保密协议**（保密项目）——明文要求。
2. **密级定密依据不明**。
3. **论文/宣传无审查条款**：这是涉密风险的高发口，必须写入。
4. **质量管理条款照抄模板却不落具体制度**：应写到设计评审、工艺评审、产品评审、审签制度、标准化审查等具体制度层面。
5. **多单位项目中质量责任主体不清**：应明确由任务总体单位或总承包单位负责组织。
6. **漏掉伦理与安全审查**（涉及生物、人体、信息安全等方向的项目）。
7. **标准执行范围写窄**：应涵盖军用标准以及其他满足武器装备质量要求的国家标准、行业标准和企业标准，并实施计量保障。

## 14. 验收标准与交付物清单

### ① 这一节要回答什么疑问
"什么状态叫完成？交给谁？怎么判定通过？"

### ② 必备要素清单
- [ ] 验收依据（任务书、合同、指南要求、国家标准/军用标准）
- [ ] 验收方式（会议验收、现场测试、第三方测试、用户单位考核、真实应用场景考核）
- [ ] 交付物清单：编号、名称、形态、数量、交付时间、接收方、验收方式
- [ ] 每项交付物的验收判据
- [ ] 验收组织方与验收专家构成要求
- [ ] 综合绩效评价的结论分类
- [ ] 未通过验收的处理
- [ ] 验收后的成果转化跟踪安排（如适用）

### ③ 可直接套用的写法
**交付物清单模板**：

| 编号 | 交付物名称 | 形态 | 数量 | 交付时间 | 接收方 | 验收方式 | 验收判据 |
|---|---|---|---|---|---|---|---|
| D1 | 【原理样机】 | 实物 | 1 台 | 节点 M2 | 【项目单位】 | 第三方测试 | 达到指标 K1、K2 |
| D2 | 【测试报告】 | 文件 | 1 份 | 节点 M3 | 【项目单位】 | 专家评审 | 结论明确、数据完整 |

**成果与考核条目模板**（快速转化模板的写法）：
> 项目成果及考核：考核项目应全面覆盖所列项目关键问题、项目技术指标、项目主要成果。考核方式应与技术成熟度等级要求一致。
— 来源：[快速转化项目建议书模板](http://www.weain.mil.cn/ywdt/1266418919119282178.shtml)

**综合绩效评价条款（民口可直接引用）**：
> 项目执行期满 6 个月内，主责单位组织专业机构依据项目任务书和有关要求分类开展综合绩效评价，由主责单位向项目承担单位下达综合绩效评价结论。项目综合绩效评价结论分为通过、未通过两类。项目综合绩效评价应突出目标导向、成果导向，注重核心目标和代表性成果，严把项目验收关。
— 依据：《国家重点研发计划管理暂行办法》第二十条（[原文](https://www.gov.cn/zhengce/zhengceku/202404/content_6947028.htm)）

**验收方式条款（民口可直接引用）**：
> 专项验收坚持成果导向，重点突出对重大标志性成果及成果转化应用情况等方面的评价，采取测试平台验证、真实应用场景考核、用户单位考核等方式，强化验收评价的客观性、针对性和科学性。
> 科技部会同主责单位在项目验收 3 年内组织对成果转化应用情况进行跟踪评价。
— 依据：同办法第二十六条、第二十一条

**军口结题验收的评审组织方式**：
> 项目转阶段和结题验收时，成立独立评审专家组，根据项目任务书或合同要求，就项目研究内容完成情况进行全面审查，并提出转阶段意见、成果转化建议。
— 依据：《关于建立装备预研共用技术领域基金类项目快速支持机制（试行）的公告》第12条（[原文](http://www.weain.mil.cn/ywdt/1266418919119282178.shtml)）

**验收与成果转化的衔接（军口可直接引用）**：
> 通过评审验收达到优秀标准的快速扶持项目，按程序报批后，成果直接转入相关渠道安排实施。通过评审验收达到优秀标准的快速转化项目，成果定期向相关单位推荐使用。
— 同上公告第13条

**存货归档义务**：
> 落实国家科技报告、科学数据汇交和科技成果汇交制度，做好有关档案的整理、保存和归档。
— 依据：《国家重点研发计划管理暂行办法》第六条

### ④ 常见错误与扣分点
1. **交付物清单笼统**（"研究报告若干"），验收时无法逐项判定。
2. **交付物无接收方**：交付物必须有明确的接收主体，否则无法闭环。
3. **验收判据与指标编号不对应**。
4. **验收方式单一**：全部为自测或全部为会议验收，缺乏第三方测试与真实场景考核。
5. **未写综合绩效评价的结论分类与时间要求**（民口项目）。
6. **漏掉档案与科学数据汇交义务**。
7. **未写未通过验收的处理路径**。

## 15. 风险与变更管理

### ① 这一节要回答什么疑问
"出事怎么办？能不能改？改的流程是什么？"

### ② 必备要素清单
- [ ] 风险清单：风险描述、等级、触发条件、应对措施、责任人、Plan B
- [ ] 风险应对预案的触发与启动程序
- [ ] 变更类型界定（重大调整 / 一般调整）
- [ ] 变更申请与审批流程、审批主体
- [ ] 不可抗力与客观困难的免责条款适用
- [ ] 项目撤销/终止的情形与后果
- [ ] 科研诚信与失信记录条款

### ③ 可直接套用的写法
**重大调整与变更审批条款（民口可直接引用）**：
> 项目实施中须作出重大调整的，由主责单位会同专业机构研究批复调整；对于因非正当理由致使项目撤销或终止的，应调查核实后严肃处理并逐级问责，对科研失信和违规行为，纳入科研诚信记录。
— 依据：《国家重点研发计划管理暂行办法》第十九条（[原文](https://www.gov.cn/zhengce/zhengceku/202404/content_6947028.htm)）

**军口免责与追责并行的条款（快速扶持项目可直接引用）**：
> 对于快速扶持项目，特别是第一阶段研究任务，对已履行勤勉尽责义务，但由于技术未知难度等客观原因难以完成预定目标的，经综合评估确认后，不追究责任；对未履行勤勉尽责义务的，一经查实，将严肃追究承研团队和所属单位责任，列入"黑名单"，并在全军武器装备采购信息网进行通报，三年内不得申报预研共用技术领域项目。
— 依据：《关于建立装备预研共用技术领域基金类项目快速支持机制（试行）的公告》第14条（[原文](http://www.weain.mil.cn/ywdt/1266418919119282178.shtml)）

**过程监督与动态调整条款（民口）**：
> 建立创新激励机制和责任追究机制。对在专项组织实施过程中作出重要贡献的单位、团队和个人，按照国家有关规定予以表彰奖励。对执行不力的，实行动态调整，并倒查各主体责任，逐级问责。对科研失信和违规行为，视情况纳入科研诚信严重失信行为数据库。
— 依据：同办法第三十五条

**监督评估依据条款**：
> 监督评估工作应以重点专项实施方案、项目申报指南、立项批复、任务书、协议等为依据，按照责权一致的原则组织开展。
— 依据：同办法第三十二条

### ④ 常见错误与扣分点
1. **无变更审批条款**：B 卷中方案与指标一旦冻结，必须有正式的变更通道。
2. **把"重大调整"与"一般调整"混为一谈**。
3. **免责条款写得过于宽松**（如"因技术难度导致未达标不追究责任"）——会与"未履行勤勉尽责义务将被列入黑名单"的规则冲突。
4. **漏掉科研诚信条款**：科研失信会被纳入科研诚信严重失信行为数据库或（军口）列入"黑名单"。
5. **监督评估依据写不全**：至少应涵盖任务书、协议、立项批复。

### ① 这一节要回答什么疑问
"材料齐不齐？能不能通过形式审查？"

### ② 必备要素清单
- [ ] 项目申报书/任务书正本（含签章页）
- [ ] 预算申报书 / 经费预算表（含财务负责人签字）
- [ ] 联合申报协议（明确各单位任务分工、考核指标、经费分配，项目负责人、课题负责人签字）
- [ ] 各参与单位任务分工与经费分配表
- [ ] 诚信承诺书（项目牵头申报单位、课题申报单位、项目负责人、课题负责人）
- [ ] 非密声明 / 非涉密证明
- [ ] 保密协议（保密项目）
- [ ] 单位资质证明（法人证书 / 营业执照等）
- [ ] 项目（课题）负责人身份证明与职称、学位证明
- [ ] 外籍/港澳台科学家聘用材料（如适用）
- [ ] 自筹经费来源证明（有配套经费时）
- [ ] 数据递交承诺书 / 科学数据汇交承诺书
- [ ] 伦理审查相关证明材料（涉生物、人体、人类遗传资源等）
- [ ] 标准初稿（标准化类项目）
- [ ] 项目汇总表
- [ ] 推荐函（推荐单位出具，加盖公章）
- [ ] 专家推荐书（走专家推荐渠道时）
- [ ] 系统填报生成的 PDF 与电子扫描件

### ③ 可直接套用的写法
**须提交的附件材料清单（民口，可直接引用其要件）**：
> （1）应严格按照指南要求提供联合申报协议（需明确各单位任务分工、考核指标、经费分配等，且需项目负责人、课题负责人签字）和数据递交承诺书；（2）企业资质证明；（3）明确有配套经费的项目，应出具自筹经费来源证明，并明确配套金额；（4）受聘于内地单位的外籍科学家及港、澳、台地区科学家作为项目（含任务或课题）负责人的，全职受聘人员应由内地聘用单位提供全职聘用的有效证明，非全职受聘人员应由内地聘用单位和境外单位同时提供聘用的有效证明。
— 依据：[科技部关于填报国家重点研发计划"ECMO系统研发"项目申报书（含预算申报书）的通知](https://www.most.gov.cn/tztg/202009/t20200916_158773.html)

**数据与成果汇交承诺**：
> 项目（课题）牵头单位须出具数据汇交承诺书。
— 依据：[河南师范大学科技处转发通知](https://www.htu.edu.cn/kyc/2026/0801/c217a401690/page.htm)

**推荐函与推荐单位要求（民口）**：
> 请各推荐单位于【时间】前通过国科管系统逐项确认推荐项目，并将加盖推荐单位公章的推荐函以电子扫描件上传。
— 依据：[上海交通大学科研院转发通知](https://keyan.sjtu.edu.cn/ky-tongzhi/20260731/6002.html)

### ④ 常见错误与扣分点
1. **附件不齐导致形式审查不通过**：形式审查明确申报材料完整性是其审查目的之一。
2. **联合申报协议三要素缺失**（任务分工、考核指标、经费分配）或漏签字。
3. **推荐函未加盖推荐单位公章**。
4. **自筹证明缺失或金额不一致**。
5. **纸质件份数与装订不合规**：国防科工局类要求项目建议书一式三份、双面打印、不得缺页少页；各主管单位报送时还须附项目建议书（或代任务书）3 份、项目汇总表 1 份以及电子文档（光盘形式）（[国家国防科工局指南通知](https://kjc.ahpu.edu.cn/_t41/2025/1106/c731a258403/page.psp)）。
6. **多头申报/重复申报**：申报单位同一个项目只能通过单个推荐单位申报，不得多头申报和重复申报（[上海交通大学科研院转发通知](https://keyan.sjtu.edu.cn/ky-tongzhi/20260731/6002.html)）；项目申报要加强与其他相关科研计划的统筹协调，确保申报渠道的唯一性，避免重复。

## 19. 安全保密专篇（2026 回标补充 · 任务书必备论证内容）

> ⚠️ **现行必备栏目（2026 回标补充）**：依 **科工技〔2026〕112 号 第二十一条(一)**（任务书阶段）明文，任务书「重点论证项目实施的可行性，具体包括技术方案、关键技术及解决途径、预期成果、技术指标和考核方式、任务分工、经费概算和**安全保密专篇**等，应明确关键节点的标志性成果和考核方式，以及**科学数据管理计划**」——「**安全保密专篇**」是**明文列出的必备论证内容**；**科工技〔2010〕136 号 第二十六条（建议书七项）与第二十八条（任务书必备条款）均未列入本项**。**两阶段论证内容不等同，不得合并引用**（建议书侧对应条款为 **第二十条(一)**，任务书侧为 **第二十一条(一)**）。依据：[科工技〔2026〕112号 第二十条(一)、第二十一条(一)](https://www7.zzu.edu.cn/jg/info/1057/1122.htm)；[136号 第二十六条、第二十八条](https://www.sastind.gov.cn/n10086167/n10086221/c10129558/content.html)
>
> **与本文 §13 的分工（重要）**：§13「保密与质量管理条款」是**条款式**——保密协议、质量制度等可签约、可追责的条款；本节是**专篇式**——112 号第二十一条(一)要求的是「**专篇**」，回答「**需按保密管理的环节怎么界定、密级依据是什么、全周期怎么管、谁检查谁负责**」。**两节并存、不可互相替代**，也不要拿 §13 里的一段话顶替本专篇。
>
> **本节边界（硬性）**：本节只给**栏目框架与写法**（公开可讨论的方法论层面）。**不得在公开文本中写出任何涉密内容，不得列举涉密事项清单，不得推测密级判定实务。**凡涉及具体密级结论、定密依据原文、保密资格等级、涉密载体与人员清单，均由承研单位保密工作机构在**涉密渠道**内出具与审定；公开稿只写**程序、职责与出处**。

### ① 这一节要回答评委/管理机构什么疑问
任务书是**契约文本**，本节要确认的是「**安全保密这条可行性是否成立**」：
1. 本项目**哪些环节、哪些产出**需按保密管理——**界定的方法与程序**是什么（不是结论本身）；
2. **密级是怎么定出来的**：定密主体、依据层级、定密时点、复核与变更，以及**与立项批复已载明"涉密等级"的对齐**；
3. 保密**制度与措施**能否覆盖全周期，能不能落到岗位、流程与节点；
4. **涉密载体与人员**怎么管，交接与清退怎么留痕；
5. **外协与协作单位**怎么管（条件核验、协议、接触面控制、泄密责任）；
6. **谁检查、多久查一次、发现问题怎么整改与追责**；
7. 走**公开路径**时，凭什么按非密报送（非密证明/非密声明的出具与留存）。

### ② 必备要素清单（六个论证模块 · 任务书口径）

**模块 1：需按保密管理事项的界定（写法框架）**
- [ ] **界定程序与主体**：「本项目需按保密管理的事项，按国家保密法律法规及本单位定密权限，由〔承研单位〕保密工作机构在〔时点〕逐项界定并出具书面结论（涉密渠道），公开稿不载其内容」
- [ ] **界定覆盖范围口径**：对工作分解结构（WBS）的**每一项任务**、每一类数据与产出、每一次外协与试验、每一次对外发表，**逐类给出"是否纳入保密管理"的判定程序**——**只写判定程序，不列举具体事项**
- [ ] **与立项批复对齐**：批复已明确「**涉密等级**」的，本专篇须与之**一致**，不得自行降低或提高；需要调整时走变更程序

**模块 2：密级确定依据**
- [ ] **依据层级与出处**：国家保密法律法规、行业定密规定、本单位定密工作制度——**只列依据类别与文号，不抄录条文内容**
- [ ] **定密主体与工作机构**、定密责任人的职责
- [ ] **定密时点**：立项/任务书签订时确定；实施中因任务范围变化而调整
- [ ] **密级标注与知悉范围**的管理要求
- [ ] **解密与密级变更**的触发条件与审批程序（项目结束、成果处置、范围收窄）

**模块 3：保密制度与措施**
- [ ] **制度清单（只写制度名称与适用范围）**：保密工作责任制、保密教育、涉密人员管理、涉密载体管理、涉密信息系统与设备管理、发表与宣传审查、外协与涉外管理、保密检查与奖惩
- [ ] **措施三线**：物理防护（场所、工位、门禁）、技术防护（涉密计算机与存储介质不得连接互联网及其他公共信息网络）、流程防护（审批链与全程留痕）
- [ ] **措施落到节点**：与本文 **§9 进度计划与节点考核**对齐，在每个节点写明该节点的保密动作（如转阶段前完成载体清点与知悉范围复核）

**模块 4：涉密载体与人员管理**
- [ ] **载体全流程**：制作、接收、传递、使用、复制、保存、维修、销毁的**审批链条与登记留痕**；不得擅自携带外出，不得在非涉密设备上处理
- [ ] **人员管理**：涉密岗位确定、**岗前保密教育**、在岗管理、**离岗（调岗/离职/退休/借调）清退与脱密期**手续；外来人员、临时聘用人员、研究生等的接触范围限制
- [ ] **信息系统**：账号与权限、审计日志、介质与外设管控、远程与移动办公限制

**模块 5：外协与协作单位的保密要求**
- [ ] **立项前条件核验**：承接单位应具备与协作内容相应的保密条件
- [ ] **专项保密协议**：保密范围、接触人员名单、涉密载体交接、成果归属、违约与泄密责任
- [ ] **接触面最小化**：能拆成非密件的拆成非密件交付；确需按保密管理的部分，按相应权限与渠道进行
- [ ] **联合承研（多单位）时的责任划分**：**主承研单位牵头责任**与各承研单位、外协单位的保密责任边界
- [ ] **外协人员进入本项目场所、参与试验的审批与陪同要求**

**模块 6：检查与责任**
- [ ] **检查**：项目组自查频次、承研单位保密工作机构检查、配合上级机关与委托专业机构检查；**检查内容与记录形式**
- [ ] **整改**：问题清单、限期整改、复查闭环
- [ ] **责任**：责任主体（承研单位、项目负责人、项目组保密责任人、外协单位）与追责依据
- [ ] **与验收衔接**：保密管理执行情况纳入项目过程管理与验收前检查范围

### ③ 可直接套用的写法
**（a）条件要求的法定句式（136 号，可直接引用）**
> 承研单位是项目实施的责任主体，应**具备法人资格和保密资质**。多个单位联合承担研究任务的，**主承研单位**为项目牵头责任单位。
> — 依据：科工技〔2010〕136号 第十二条（[原文](https://www.sastind.gov.cn/n10086167/n10086221/c10129558/content.html)）；另见同办法第九条「国防基础科研项目管理按照**保密管理的有关法律法规**执行」

**（b）现行总纲句式（112 号，可直接引用）**
> 涉密科研项目严格执行保密管理有关规定。**承担有保密要求科研项目的单位，应具有相应资质。**
> — 依据：科工技〔2026〕112号 第十条（[原文](https://www7.zzu.edu.cn/jg/info/1057/1122.htm)）

**（c）任务书批复与专篇的一致性句式**
> 立项批复与任务书批复均应明确**涉密等级**；任务书申报内容须与批复保持一致，不得自设或自行调整密级。
> — 依据：科工技〔2026〕112号 第二十条(四)（立项批复含"涉密等级"）、第二十一条(三)（任务书批复含"涉密等级"）（[原文](https://www7.zzu.edu.cn/jg/info/1057/1122.htm)）

**（d）专篇总起句模板（放在本节开头，先划边界）**
> 本项目安全保密工作按国家保密法律法规与本单位保密管理规定执行。**需按保密管理的事项、密级结论及其定密依据，由承研单位保密工作机构在涉密渠道内逐项界定并出具**；本专篇陈述其**界定程序、责任分工、管理措施与检查追究安排**，不载具体涉密内容。

**（e）模块化模板句（六个模块各一句，可直接改写）**
> 【界定】本项目以工作分解结构（WBS）为底稿，对每项任务、每类数据与产出的保密管理属性逐项判定，判定程序为〔……〕，判定结论由〔保密工作机构〕出具。
> 【密级】本项目密级依据〔依据类别与文号〕确定，定密工作由〔主体〕承担，定密责任人为〔岗位〕；项目实施中任务范围发生实质变化时，按〔程序〕办理密级变更或解密。
> 【制度与措施】本项目执行〔单位〕保密工作责任制等〔N〕项保密制度；技术防护上，涉密计算机与存储介质**不得连接互联网及其他公共信息网络**；在〔节点名称〕等关键节点同步完成载体清点与知悉范围复核。
> 【载体与人员】涉密载体的制发、传递、使用、复制、保存、维修、销毁按审批链条办理并登记留痕；涉密人员上岗前接受保密教育，离岗时按离岗保密管理规定办理清退手续。
> 【外协】外协前由〔单位〕核验承接方相应条件并签订专项保密协议；外协内容能拆分非密件的按非密件交付，确需按保密管理的按相应渠道进行。
> 【检查与责任】项目组每〔季度/半年〕自查一次，配合〔单位保密工作机构〕与上级检查，问题限期整改、复查闭环；违反保密规定的按〔本单位制度/国家有关规定〕追究责任。

**（f）发表与宣传审查句式模板**
> 项目组成员对外发表论文、申请专利、参加学术会议、公开宣传报道及研究生学位论文，均须按「**先审查、后公开**」程序报〔单位保密工作机构〕审查批准；未经批准不得对外提供本项目任何技术资料与数据。

**（g）材料报送与递送句式模板**
> 项目材料按〔公开路径：单位保密部门出具的非密证明/非密声明 + 在线报送〕或〔涉密路径：保密资质证明 + 专人送往或机要邮寄〕执行；**不得经互联网或普通邮政、快递提交**。
> — 依据：112号第十七条（分级分类发布）；[大连理工大学《关于进一步规范国防科研项目申报过程保密管理的通知》](http://scidep.dlut.edu.cn/info/1070/23008.htm)

### ④ 常见错误与扣分点
1. **整节缺失**：只按 136 号第二十八条写任务书必备条款（研究目标与技术指标、技术方案、预期成果、任务分工、经费细化测算），文本里就没有这一节——**形式审查／初审阶段最容易被退回的漏项**。
2. **用 §13 的一段话顶替专篇**：112 号要的是**专篇论证**，条款式保密约定不能替代。
3. **只写密级、不写界定程序与定密依据**：管理机构要看的是「你怎么定、谁定、按什么定」，不是一句结论。
4. **与批复的「涉密等级」不一致或自行降级**：任务书必须与批复对齐，不得自设目标、自调密级。
5. **措施不落岗位、不落节点**：与 §9 节点表脱钩的保密措施不可考核，等于没写。
6. **外协无协议、无条件核验、无接触面控制**：多单位联合项目这是最常见的责任断点。
7. **人员离岗清退与载体销毁无程序**：项目结束或人员流动时风险集中暴露。
8. **缺发表审查与涉外审批**：论文、会议、学位论文、参展是高风险口。
9. **检查与责任不写**：没有检查频次、没有整改闭环、没有追责依据，专篇就只是表态。
10. **把只能来自内部文件的内容写进公开稿或上传互联网**：这已不是文本质量问题，而是保密违规。

## 20. 科学数据管理计划（2026 回标补充 · 任务书必备论证内容）

> ⚠️ **现行必备栏目（2026 回标补充）**：**科工技〔2026〕112 号 第二十一条(一)**（任务书）明文要求任务书明确「**科学数据管理计划**」（建议书侧对应条款为 **第二十条(一)**）。**两阶段论证内容不等同，不得合并引用**。136 号（2010）第二十六条七项与第二十八条必备条款均未列入本项。依据：[科工技〔2026〕112号 第二十条(一)、第二十一条(一)](https://www7.zzu.edu.cn/jg/info/1057/1122.htm)；[136号 第二十六条、第二十八条](https://www.sastind.gov.cn/n10086167/n10086221/c10129558/content.html)
>
> **与 §12 知识产权、§14 验收交付物的关系**：本节的**数据集与配套文档要落成可交付物**，并与 §12 的成果标注、§14 的验收标准对齐——任务书里写了的数据管理承诺，就是将来验收时的检查项。**需按保密管理的数据不在本节展开**（其存储与使用按 §19 与保密渠道执行），本节只写**公开侧的数据管理安排与隔离规则**。

### ① 这一节要回答评委/管理机构什么疑问
1. **任务要产生哪些数据**，规模量级与存储位置分别是什么；
2. 数据**质量与可复用性**靠什么保证（采集规程、元数据、两级校验）；
3. **谁对数据负责**，交接怎么办；
4. **公开数据与需按保密管理的数据怎么隔离**，各走什么通道；
5. **共享、汇交的对象、时限与形式**分别是什么；
6. **项目结束后数据去哪**（保留、移交、开放或销毁），以及方案**变更**怎么走程序。

### ② 必备要素清单（任务书口径：每条都要能落到交付物与节点）
- [ ] **数据清单（表格式）**：数据类别 ｜ 产生环节（对应 WBS 任务号） ｜ 规模量级 ｜ 存储位置 ｜ 责任人 ｜ 是否对外共享 ｜ 对应交付节点
- [ ] **采集与质量控制**：采集规程、仪器与工况记录要求、重复试验与校验方法、异常数据处理与留痕规则
- [ ] **元数据与数据字典**：字段定义、单位、时间戳、环境条件、版本号——**没有元数据的数据集不可复用，验收时容易被判"成果形态不成立"**
- [ ] **存储、备份与保存期限**：存放位置（单位平台／服务器）、备份频率与介质、保存期限、介质更换与迁移安排
- [ ] **分级分类与隔离规则**：按单位与国家有关规定分级分类；**公开数据与需按保密管理的数据不得混存、混用同一平台**（后者按保密渠道存储使用，不在公开稿展开）
- [ ] **共享与使用审批**：对外提供／共享的条件、审批层级、使用协议与引用要求
- [ ] **汇交安排**：汇交对象（单位数据管理平台／指定数据机构）、**时限、形式**，以及汇交物与验收材料的对应关系
- [ ] **数据责任人**：数据管理员／项目负责人职责、人员变动时的交接程序
- [ ] **数据知识产权与成果标注**：数据集作为成果时的归属、引用与标注方式（与本文 §12 一致）
- [ ] **与节点考核绑定**：数据集与配套文档写入 **§9 节点表**的交付物栏，明确「提交形式 + 检查方式」
- [ ] **项目结束后的处置**：保留、移交、开放或销毁的决定程序与责任人
- [ ] **变更程序**：数据管理方案变更的申请、审批与备案流程（与 §15 变更管理一致）

### ③ 可直接套用的写法
**（a）法定依据句式（可直接引用）**
> 项目任务书应明确「**科学数据管理计划**」。
> — 依据：科工技〔2026〕112号 第二十一条(一)（[原文](https://www7.zzu.edu.cn/jg/info/1057/1122.htm)）；建议书侧同一要求见第二十条(一)

**（b）总体原则与责任句式模板**
> 本项目科学数据管理遵循「**谁产生、谁负责；分级分类、安全可控；能用可查、应存尽存**」原则；项目负责人对数据质量与安全负总责，数据管理员〔岗位〕负责日常管理，〔承研单位〕负责提供存储与备份条件。

**（c）数据清单句式模板**
> 本项目数据按「数据类别—产生环节（WBS 任务号）—规模量级—存储位置—责任人—是否共享—交付节点」逐项列表（随任务书附件提交），作为数据管理检查与验收比对的底稿。

**（d）质量、元数据与校验句式模板**
> 每类数据在采集时同步记录〔试验条件／设备型号与编号／环境参数／采样率／时间戳〕等元数据，字段定义与单位按〔本单位数据规范／项目数据字典〕执行；数据入库前经〔自检 + 复核〕两级校验，不合格数据标记留痕，**不得覆盖原始记录**；校验记录随节点材料提交。

**（e）隔离与共享句式模板**
> 项目数据按〔单位数据分级分类规定〕分级管理；**对外发布、共享或汇交的数据须经〔项目负责人 + 单位数据／保密管理部门〕审查批准**；需按保密管理的数据按保密管理规定在相应渠道内存储与使用，**不进入对外共享库**，也不与公开数据共用存储与备份介质。

**（f）节点绑定与验收衔接句式模板**
> 在〔节点名称〕，承研单位提交〔数据集名称 + 配套说明文档 + 校验记录〕作为该节点交付物之一，提交形式为〔形式〕，检查方式为〔自查/第三方测试/专家确认〕；上述交付物列入验收范围。

**（g）项目结束处置句式模板**
> 项目结束后，数据集按〔保留期限〕在〔存储位置〕保留，并按〔汇交流程〕向〔对象〕汇交；需移交或销毁的，由〔责任人〕按〔程序〕办理并留存记录。

### ④ 常见错误与扣分点
1. **整节缺失**——112 号明文要求；且它与安全保密专篇是**两节并列**，合成一节写会同时丢两项。
2. **写成「数据保密说明」**：本节回答的是**数据全生命周期管理**，不是保密制度的复述。
3. **没有数据清单与责任人**：任务书是契约，没有清单与责任人就没有可检查的对象。
4. **数据集不写入 §9 节点表**：写了管理计划却不绑定节点与交付形式，验收时无从核对。
5. **元数据与采集规程缺失**：成果形态中的「数据库／数据集」在验收时容易被判不成立。
6. **公开数据与需按保密管理的数据混存同一平台或同一备份介质**：**风险等级最高的写法**，必须写明隔离与分渠道。
7. **汇交对象、时限、形式不写**：只写「按规定汇交」等于没写。
8. **与 §12 知识产权、§14 验收交付物口径不一致**：同一数据集在两节里的归属、标注、提交形式必须一致，否则任务书内部自相矛盾。
9. **项目结束后的处置无人负责**：数据留存期限、移交或销毁程序缺失。
