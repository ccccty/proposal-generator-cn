# 11 · 去 AI 味润色与 humanizer 交接

> **定位**：本文件是 SKILL.md §7 第 6 步的执行细则。规则清单由 `humanizer` 技能提供（其条目源自 Wikipedia《Signs of AI writing》），本文件只解决项目书里的三件事：**哪条照做、哪条会误杀、怎么验收**。
>
> **权威顺位**：SKILL.md §1 文体铁律 > §1.2 论证结构 > 本文件 §4 冲突表 > humanizer 通用规则。本文件的判据写在"原因"列，不绑定 humanizer 的条目编号；它改版重排时，按判据对齐即可。

## 1. 为什么项目书要单独加这一道

`check_proposal.py` 查的是**元信息**（【待核实】、来源标注、URL、自查表……）；这一道查的是**腔调**。两类问题不重叠：

| 痕迹类型 | 典型样子 | 谁抓得到 |
|---|---|---|
| 模板腔 | 「不是 A，而是 B」「不仅……更……」「X——Y」「**小标题：**」 | 只有本工序 + `check_style.py` |
| 套话 | 「深度融合」「赋能」「具有重要意义」「随着……的快速发展」 | 只有本工序 + `check_style.py` |
| 空转句 | 每句都通顺，删掉不损失信息（「这一点尤为重要」「这正是关键所在」） | 只能人读 |
| 元信息 | 【待核实】、来源、URL、草稿声明 | `check_proposal.py` |

评审读法上，这些痕迹和"技术内容错"是两种失败：前者不让你出局，但会让你在"研究方案及技术途径 30 分""创新性 30 分"（§8）里拿不到内行分。制度面上，基金委 2026 通告明文"不得使用由生成式人工智能直接生成的申请书"（§5）；去掉模板腔是这条红线的落点之一，但**不等于可以隐瞒 AI 使用**——声明与标识仍按 §5 规定的位次放置。

**工序边界**：这一道不产生任何新事实、不改变技术判断。改完更通顺但多出一个数字、型号或结论，就是改错了。

## 2. 什么时候跑、跑几轮

| 项 | 规定 |
|---|---|
| 时机 | §7 第 1–5 步全部完成、`check_proposal.py` 无 error 之后；`md2docx.py` 转换**之前** |
| 载体 | 只改 `正文.md`，**不许直接改 `.docx`**（会破坏 OMML 公式与段落结构，下次重转即丢） |
| 副本 | 润色前另存 `草稿/正文.润色前.md`，用于 diff 与回滚 |
| 轮次 | 按 §6 分轮推进，不要一次重写全文 |
| 跳过 | 仅当用户明确要求保留原措辞。跳过时仍跑 `check_style.py` 记数，并在交付说明注明"未做去 AI 味润色（用户要求）" |

## 3. 交接契约：只改散文

| 对象 | 允许 | 禁止 |
|---|---|---|
| 句子 | 长短、语序、连接词、拆句合句、同义替换 | 改变陈述的事实或判断强度 |
| 段落 | 切分、合并（不跨节）、删掉不承载信息的句子 | 打乱 §1.2 第 3 条要求的闭环收束 |
| 章节 | — | 编号体系（一、/（一）/1./1.1）、标题文字、节序 |
| 公式 | — | `$...$` 与 `$$...$$` 内部一个字符（含反斜杠命令）、$$ 符号的数量与配对 |
| 表格 | — | 结构、行列数、单元格里的数值与措辞 |
| 图表 | — | 图号表号序列、题注文字、图片路径 |
| 事实 | — | 数值、单位、百分比、量级、标准号（GJB…）、型号、机构与学者姓名、年份、指南原文、承诺书条款 |
| 篇幅 | 小幅下降 | 研究内容占比跌出 60–70%（§1.2 第 4 条） |

**操作阈值**：全文去空白字数下降超过 15%，先按"删掉了论证"处理，回退重做，再逐段找原因。

## 4. 冲突消解：§1 优先（humanizer 逐条对照）

| humanizer 条目 | 项目书里怎么做 | 原因 |
|---|---|---|
| §1 不是 X 而是 Y（含跨句、反向"而非"） | 照改。唯一例外：与**具名**现有技术/方法的对照，对照对象在文中出现过，可留一句 | 军口文体直接给结论；否定铺垫不承载信息 |
| §2 一句话收束、金句、戏剧化短句 | 保留三类收束："因此需要……""实现……""为本项目研究奠定了技术基础"；删掉纯重复式（"这正是关键所在""这一点尤为重要"） | §1.2 第 3 条要求每段闭环；带新信息的短句 humanizer 自身也留 |
| §3 假装深刻的说法（"真正的问题是""本质上是"） | 照改，直接写判据或判据所依赖的量 | 说破不如给判据 |
| §4 分级铺垫（"让我们先看""下面分三点"） | 照改 | 正文没有"讲解"的位置（§1.1 第 10 条） |
| §5 与无人争辩（"有人可能认为……"） | 照改；保留"与现有方法相比，A 方法在……条件下失效"这类有具名对象的对照 | 创新点必须有对照组（§7 第 2 步） |
| §6 三连排比 | 编号并列保留：三个分技术、三条创新点、指标表的列；散文里的同义三连合并或展开 | 条目结构是评审要求，不是修辞 |
| §7 重复主语句 | 连续三句以上同主语才改 | 技术段落里"该方法""该系统"是必要指代 |
| §8 破折号、空格连字符 | 正文 0 容忍：改逗号、冒号、括号或拆句 | 图号 `图4-1` 的连字符、数值区间（2019—2021）不算破折号 |
| §10 句后连字符 | 不适用 | 中文不靠连字符；英文缩写（SAR / CFR / TRL / GJB）不拆、不改大小写 |
| §12 过用词 | 按本文件 §5 的中文词表替换 | 词表要对准本行业读法 |
| §13 拔高意义 | 照改，落到具体能力缺口：缺这项能力在哪一步、导致什么后果 | "具有重要意义"不是论据 |
| §15 悬挂 -ing | 照改。中文对应形态是"……，体现了……""……，为……提供支撑"这类后置小句 | 悬挂小句把结论挂在半空 |
| §16 销售腔 | 照改。"面向……需求"本身不算销售腔，只要后面接得上具体组成 | 评审判的是技术，不是卖点 |
| §17 借用权威（"专家认为""研究表明"） | 照改：点名机构/学者 + 年份（§1.2 第 2 条）；点不出来就删 | 无主体的"研究表明"在项目书里等于未取证 |
| §18 绕开"是 / 有" | 照改（"起到了……的作用"→"是……"；"具有……的特点"→"具备……"） | 简单动词更硬 |
| §19 加粗 | 正文与表格 0 加粗；层级用标题与编号 | 加粗在申报件里没有语义 |
| §20 装饰标题 | 去 emoji、箭头、装饰横线、与正文首句重复的标题行 | 装饰一多就像模板 |
| §21 弯引号 | 不作为判据：引号样式随本单位模板，全文一致即可 | 编辑软件自动转换 |
| §22 聊天残留 | 0 容忍；交付说明里也不写"希望对您有帮助""如需调整请告知" | 这是聊天的话，不是申报件的话 |
| §24 标题后重复一句 | 照改 | 重复不增加信息 |
| §25 写文档自身（"本文档""以下表格说明"） | 照改 | §1.1 第 10 条 |
| §26 重述读者已知 | **不适用** | 项目书是独立送审文本，评委没有任何上下文，该重述的背景必须留；只在给用户的对话回复里适用 |
| 人味、个性、情绪 | **不适用** | 项目书要保持密实技术论述（§1.2 第 4 条），不引入第一人称感想、比喻、设问、幽默 |

## 5. 中文 AI 味对照表（项目书高频）

| 原写法 | 改成 | 说明 |
|---|---|---|
| 在……的大背景下 / 随着……的快速发展 | 直接给威胁环境、需求来源、型号约束或试验事实 | 背景句是铺垫，不是论据 |
| 具有重要意义 / 意义重大 | 写清能力缺口：现在缺什么，缺了会在哪一步出问题 | 意义要可指认 |
| 深度融合 / 全方位 / 多维度 / 多层次 | 写清是哪几个量、在哪一步联合处理 | 给不出量的"融合"等于没说 |
| 赋能 / 助力 / 抓手 / 新范式 / 生态位 / 组合拳 / 痛点 | 删 | 项目书里没有对应实体 |
| 值得注意的是 / 不难看出 / 众所周知 / 综上所述 | 删，直接给判断 | 提示读者注意，说明句子本身不够重 |
| 不仅……更…… / 不但……而且…… | 拆成两句 | 递进关系一般可以直接陈述 |
| 为……提供有力支撑 / 奠定坚实基础 | 写支撑了哪个指标、哪个环节、由谁验收 | 支撑要落到可核对的落点 |
| 打造 / 构建……体系 | 说清体系由哪几部分组成（分技术 1/2/3） | 体系是组成，不是形容词 |
| 大量实验表明 / 研究表明 / 实践表明 | 点名机构、年份、条件与量级；或改用本项目数据与公开规范的确定结论 | 无主体的"表明"不可核 |
| 首次提出 / 首创 | 在……范围内未见公开报道（§7 第 2 步已定） | 更稳且可辩护 |
| 显著提升 / 大幅提高 / 效果明显 | 给数（§9 第 8 条已禁） | 无基线即无指标 |
| 有效地 / 很好地 / 较好地 | 删 | 效果由数值承担 |
| 旨在 / 致力于 | 用于 / 针对 / 实现 | 公文腔换成动作 |
| 一是……二是……三是…… | 保留 | 军口公文的常规句式，不是 AI 腔；但每条后面必须接具体内容 |
| 一段里三句排比 + 破折号 + 加粗小标题 | 三样一起出现就是模板腔，全拆 | 单用可容忍，叠加即暴露 |
| 综上，本项目将…… | 删掉"综上"，直接写最终要交付什么 | 收束句不靠"综上"成立 |

## 6. 执行节奏（长文不要一次重写）

1. **摘要与立项依据**一轮：这两处最容易写成"随着……大背景下"。
2. **研究现状**一轮：演进链最容易被写成平铺综述；按 §1.2 第 2a 条的链式结构逐段核。
3. **研究内容各分技术**逐节一轮：这是篇幅主体（60–70%），也最容易出现三连排比与加粗小标题。
4. **指标论证**一轮：五拍结构不动，只改句子；"因此定为该值"必须留。
5. **团队 / 经费 / 进度 / 成果**一轮：套话最集中，删得最多。
6. 每轮结束：跑 `check_style.py 正文.md` 记错误数；对 `草稿/正文.润色前.md` 做 diff 抽查数值、公式、编号。

**两条操作纪律**：

- 只做句级、段级改写。**整章重写是丢数值与论证的最快路径**。
- 改不动的句子，通常是信息不足的句子。回到 §1.3 决定"补事实"还是"整句删"，不要靠润色硬救。

**调用提示（每轮可直接复用）**：

> 只对「{{章节名}}」做语言层润色：按 humanizer 的规则删否定对照、破折号、加粗小标签、拔高意义与套话；保留全部数值、单位、公式、表格、编号、题注与本节收束句；不新增任何事实；改动只写回 `正文.md` 的对应章节。

第一轮跑完先看 `check_style.py` 的错误数是否下降，再决定是否进入下一轮；连续两轮错误数不变，说明剩下的命中都是刻意保留项，写进自检报告即可。

## 7. 无 humanizer 时的降级清单（12 条，逐条打钩）

宿主环境没有 `humanizer` 技能时（未安装，或换了只认自家技能目录的客户端），按下表人工过一遍，交付说明注明"未加载 humanizer，按内置清单降级"。

- [ ] 1. 全文搜中文破折号、短破折号、空格连字符，逐个拆句
- [ ] 2. 搜"不是 / 并非 / 而非 …… 而是"，拆成直接陈述
- [ ] 3. 搜"不仅 / 不但"，拆成两句
- [ ] 4. 删掉全部加粗标记
- [ ] 5. 删掉 emoji、箭头字符、装饰横线
- [ ] 6. 删"综上所述 / 值得注意的是 / 不难看出 / 众所周知"
- [ ] 7. 删"赋能 / 助力 / 抓手 / 深度融合 / 全方位 / 多维度"（技术义的"闭环"保留）
- [ ] 8. "为……提供支撑 / 奠定基础"改成具体指标或环节
- [ ] 9. "具有重要意义"改成能力缺口的后果
- [ ] 10. "大量实验表明 / 研究表明"点名到机构学者，或删
- [ ] 11. 每段末句自检：删掉是否损失信息？损失则留，不损失则删
- [ ] 12. 跑 `check_style.py` + `check_proposal.py` 复核，两条都过再交付

## 9. 边界与不做的事

- **引用原文不改写**：指南条目、承诺书条款、法规条文的引用文字一个字不动，改了就和原件对不上。
- **术语不改造**：中英混排的 SAR、CFR、TRL、GJB 不改大小写、不加空格、不拆连字符。
- **不引入新修辞**：去掉模板腔之后不需要补"人味"，不加比喻、设问、排比、第一人称感想。
- **不替代人工核实**：这一道只处理"怎么写得像内行"，不处理"写的是否为真"；事实核实仍在用户（§5）。
- **不做全自动判定**："像不像本行内人"最终靠人读；本工序只保证可机械判定的部分为 0，其余按 §6 的抽读兜底。
