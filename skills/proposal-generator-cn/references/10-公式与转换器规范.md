# 10 · 公式写法与转换器规范

> **本文件是公式与排版工具的唯一权威**。SKILL.md §1.6 只保留标记方式与四原则，
> 命令白名单、转换器行为、排版配置一律以本文件为准。
> 依据：对 `tools/latex_omml.py` 的实测行为（2026-10 复测），不是文档转述。

## 1. 标记方式

| 场景 | 写法 | 转换结果 |
|---|---|---|
| 独立行公式 | 上下空行、独占一行，``$$...$$` | `m:oMathPara`（居中独立公式） |
| 行内公式 | `$...$` | `m:oMath`（嵌入正文） |

转换由 `tools/md2docx.py` 完成，输出 Word 原生 OMML——不是图片、不是 MathType 对象。

### 1.1 符号说明必须行内成段（反面典型，最常见）

公式后的「其中 … 为 …」是一句话，**整句是一个段落**，符号用行内 `$...$` 嵌在句中。
禁止把每个符号单独写成一行公式再逐行解释——那会在 Word 里变成「一个符号一段、一句解释一段」
的竖排清单，公式居中独占一行，正文被切成碎片，评委一眼看出是机器排版。

```markdown
<!-- 正确：一句话写完所有符号 -->
其中 $G_{\mathrm{geo}}$ 为由观测几何改善带来的信噪比增益，$T_{\mathrm{man}}$ 为机动执行时间，$w_{1}$、$w_{2}$、$w_{3}$ 为权重。

<!-- 错误：每个符号单独起行（无论用 $$ 还是单独一段 $ $） -->
其中

$$
G_{\mathrm{geo}}
$$

为由观测几何改善带来的信噪比增益，

$$
T_{\mathrm{man}}
$$

为机动执行时间，
```

同一规则适用于三处容易写错的场合：

| 场合 | 正确写法 | 错误写法 |
|---|---|---|
| 多个并列符号 | `其中 $w_{1}$、$w_{2}$、$w_{3}$ 为权重` | 每个权重各起一行 |
| 段内取值代入 | `当剩余窗口长度大于 20 秒时取 $w_{2} = 0.2$，允许…` | 把 `$w_{2} = 0.2$` 单列一行 |
| 公式后紧跟结论 | `取 $B = 20$ MHz，则 $\Delta R = 7.5$ 米。` | 数值单列一段 |

**只有需要被后续引用、带编号、或跨行推导的式子**才用 `$$...$$` 独立成行；
解释性符号、取值、单位、判据一律行内。

### 1.2 转换器的段落行为（v1.3.1 起）

- `$...$` 在原段落内就地渲染为 `m:oMath`，与文字 run 交替排列，**不拆段、不换行、不居中**。
- `$$...$$` 才是独立块：空的居中段落 + `m:oMathPara`。
- 转换后自检：`verify_docx.py` 报告「段落数」应明显小于「文字段 + 行内公式数」之和；
  若发现大量只有公式、没有文字的段落，说明 md 里把符号写成了独立公式行。

| 根式 | `\sqrt{x}` `\sqrt[n]{x}` | |
| 上下标 | `^{...}` `_{...}`（单字符可省略花括号） | 作用到前一个原子 |

## 3. 不支持的命令（写了会原样出现在公式里，必须避免）

| 命令 | 处理方式 |
|---|---|
| `\begin{cases}...\end{cases}`、`\pmatrix`、`\bmatrix`、array 等环境 | 不支持矩阵/分段环境。改法：分行写成多个独立公式，或用 `\left\{ \right.` 加文字说明 |
| `\check \breve \acute \grave` 等少见重音 | 改用文字或 `\hat`/`\bar`/`\tilde` |
| `\substack` `\overset` `\underset` `\stackrel` | 改用多行公式 |
| `\color` `\textcolor` `\boxed` | 颜色与边框请在 Word 里手工设置 |
| 自定义宏 `\newcommand` | 不支持 |
| 未列入 §2 的任何反斜杠命令 | 原样输出（可见反斜杠），转换时产生告警 |

**关键行为（与直觉不同，务必知道）**：不支持的命令**不会报错、也不会自动降级**，
而是把命令名当成普通文字留在公式里——评审会直接看到 `\tilde{x}`。因此必须：

1. 用 `md2docx.py --strict` 生成，出现告警即修正；
2. 用 `verify_docx.py` 复查成品，残留反斜杠会被判为错误。

## 4. 公式撰写五原则

1. **每公式必解释变量**，一句即可，不写教科书。
2. **公式嵌入论证链**：为什么需要它 → 公式 → 它推出的结论或数值。
3. **禁止装饰性公式**：每个公式都必须是后续论证的前提。
4. **数值与公式分离**：公式给关系，数值代入写在外面。

   取 `B = 20` MHz，则 `\Delta R = 7.5` 米；而 `R = \frac{c}{2B}` 只表达带宽与分辨力的关系。

5. **符号说明行内成段**：变量解释、取值代入、单位换算都用 `$...$` 写在句子里，
   **不得把单个符号排成独立公式行**（见 §1.1）。判断标准：这句话读出来是不是一句完整的中文？
   是就要连成一段。

密度要求：研究内容章每个分技术 3–5 个核心公式；总量 25–35 个（独立行 + 行内混合）。

## 5. 排版配置（不写死在任何机器上）

默认排版只是"可用的起点"，**最终以本单位当年度转发模板为准**。默认值：

| 项 | 默认值 | 备注 |
|---|---|---|
| 正文 | 宋体 小四（12 pt） | 与国重研发申报书《填报说明》一致 |
| 一级标题 | 黑体 四号（14 pt） | 同上 |
| 二级标题 | 黑体 小四（12 pt） | |
| 三级标题 | 楷体 小四（12 pt） | |
| 表格/题注 | 宋体 五号（10.5 pt） | |
| 页边距 | 上下 2.5 cm，左右 2.8 cm | 173 模板实测值 |
| 行距 | 1.5 倍 | **原参照件该数值不可辨识**，按单位模板改 |
| 首行缩进 | 2 字符 | |
| 图宽 | 5.5 英寸 | |

修改方式：先导出默认配置，改成自己的，再引用。

    python tools/md2docx.py --print-default-config > format.json
    python tools/md2docx.py 正文.md 正文.docx --config format.json

也可只覆盖需要的键（其余取默认值）：

    {
      "fonts": { "body": "仿宋_GB2312" },
      "sizes": { "body": 12 },
      "line_spacing": 1.25,
      "margins_cm": { "left": 3.0, "right": 3.0 }
    }

## 6. 图与表

- 图：`![图1-1 总体技术路线图](图源/图1-1.png)`，或图片行之后单独一行写题注；
  两种写法不要同时用（转换器会自动去重，但保持一种更清晰）。
- 题注识别：以"图+数字"或"表+数字"开头的行会被识别为图表题注，居中、五号。
- 图片缺失会告警；`--strict` 下直接失败。
- 技术路线图的 drawio 源文件统一存 `图源/` 子目录，与 .docx 分开交付。
