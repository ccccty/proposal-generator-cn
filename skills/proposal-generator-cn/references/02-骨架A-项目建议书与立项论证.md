# 骨架A：项目建议书 / 立项论证材料

> 适用场景：国防科技173计划技术领域基金、军委装备发展部装备预研"快速支持"项目、国防科工局基础科研/强基工程、军科委前沿创新类项目，以及国家重点研发计划预申报、国家自然科学基金等需要"先论证、后立项"的项目。
>
> 与 B 卷的关系：A 卷是**"说服评委立项"的论证文本**，B 卷是**"约束承担方履约"的契约文本**。A 卷的论证结论会被摘取成 B 卷的指标与交付物，因此 A 卷里出现过的每一个数字，都必须能在 B 卷里被考核。
>
> 编制日期：本文件为通用骨架，不针对任何具体年度指南。

## 0. 总纲：两份"口径"的术语对照表

同一个论证内容，军味口径与通用科研口径的写法差异极大。**先把这张对照表记住，再动笔**——用错口径是评审专家第一眼就能看出的"外行信号"。

| 论证维度 | 军味 / 国防口径 | 通用科研口径（自科基金、重点研发计划等） |
|---|---|---|
| 研究的起点 | 国家/军队需求牵引（作战需求、装备体系短板） | 科学问题（Scientific Question） |
| 为什么要做 | **必要性**：不解决会卡住哪个装备/哪型任务 | **立项依据**：该科学问题为何尚未解决、学术价值何在 |
| 创新的落点 | **装备体系贡献度**、作战使用场景、体系能力增量 | 学术贡献、理论突破、方法创新 |
| 成熟度语言 | **技术成熟度 TRL / 装备预研阶段**（概念、原理验证、关键技术攻关、演示验证） | 研究阶段（基础研究、应用基础研究、技术开发） |
| 指标语言 | 战术技术指标、使用要求、考核验证条件 | 研究目标、预期成果、考核指标 |
| 指标达成方式 | 第三方测试 / 靶场试验 / 原理样机实测 / 仿真对比 | 实验验证、理论证明、数值模拟 |
| 成果形式 | 原理样机、演示验证系统、试验报告、国防专利、军用标准（GJB）建议稿 | 论文、专著、专利、软件著作权、数据集 |
| 交付标准 | **验收**（是否达到《研制任务书》/合同要求） | **结题/综合绩效评价** |
| 风险语言 | 技术风险、进度风险、配套风险、**"卡脖子"与外协依赖风险** | 研究风险、技术路线风险 |
| 保密要求 | 密级标注、非密声明、脱密处理、保密资质 | 数据安全、伦理审查、科学数据汇交 |

**术语依据**：
- 军味口径的需求牵引与体系贡献表述，见《新时代的中国国防》白皮书对"机械化建设任务尚未完成、军事安全面临技术突袭和技术代差被拉大的风险"的表述（[《新时代的中国国防》，2019](https://www.gov.cn/zhengce/2019-07/24/content_5414325.htm)）；以及《武器装备质量管理条例》第九条"武器装备论证质量管理的任务是保证论证科学、合理、可行，论证结果满足作战任务需求"（[国务院、中央军委令第582号](https://www.gov.cn/zhengce/2010-10/08/content_2602566.htm)）。
- 技术成熟度语言见 GJB 7688-2012《装备技术成熟度等级划分及定义》，其术语体系包含 technology readiness、technology readiness levels、operational environment、relevant environment、laboratory environment、breadboard、brassboard、prototype（[GJB 7688-2012 全文 PDF（高校转载）](https://clxy.hebut.edu.cn/docs/2023-05/62892dc2ad734031a371848825b4fc63.pdf)）。
- 通用科研口径的科学问题导向，见国家自然科学基金委 2026 年申请书改版说明："调整后的申请书正文包括立项依据、研究内容及研究基础三部分……研究内容部分不再预设提纲限制"（[国家自然科学基金委：关注！！！2026年申请书改版](https://www.nsfc.gov.cn/p1/3381/2821/99242.html)）。

## 2. 封面与密级标注

### ① 这一节要回答评委什么疑问
"这份材料我能不能看、能不能传、有没有走对渠道？"

形式上，密级标注回答的是**形式审查**问题。国防科工局的形式审查要求明确：不符合规定的项目建议书不得通过形式审查，终止项目立项（[《国防科工局技术基础科研项目建议书形式审查内容及要求》第十三条](https://www.sastind.gov.cn/n10086167/n10086221/c10129631/content.html)）。

### ② 必备要素清单
- [ ] 密级（★关键）：173 模板封面首行即为"密级:"；快速支持三套模板封面首行同样为"密级:"或"密级："
- [ ] 项目名称（173 模板提示："应填写所申报指南的项目编号和名称"）
- [ ] 申报单位全称（173 模板提示："填写与公章一致的单位名称，须加盖公章"）
- [ ] 参研单位（173 模板提示：与公章不一致的参加单位"须在此处填写"）
- [ ] 项目负责人（173 模板提示：须"亲自签名"）
- [ ] 联系人、联系电话、通信地址
- [ ] 研究期限、研究经费
- [ ] 申报人（项目申请人）签字 + 日期
- [ ] 申报单位（盖章）+ 日期
- [ ] 承诺声明（173 模板含两段：项目负责人诚信承诺、申报单位诚信承诺；快速转化模板与快速支持模板另有"非密声明"要求）

### ③ 可直接套用的写法
**项目名称**（军味）：
> 【技术名称】用于【作战平台/装备对象】的【关键技术方向】研究

**项目名称**（通用科研口径）：
> 面向【应用场景】的【技术名称】【方法/机理】研究

**承诺声明句式**（改写自173模板承诺栏，请以本单位实际模板文本为准）：
> 本人保证所填写信息真实有效。如有涉密信息，愿承担全部法律责任。如有不实，愿承担相应的法律责任。
> 本单位对提交的材料进行了审核，保证所填写信息真实有效，如有不实，愿承担相应的法律责任。

**送审说明句式**（当指南按内部事项管理时，必须写进去）：
> 本《指南》按照内部事项管理，相关内容不得通过互联网传播；项目建议书已进行脱密处理，申报单位出具非涉密证明（加盖单位公章）。
— 依据：南昌大学科学技术处转发通知原文即含此要求（[关于征集国防科技173计划技术领域基金2021年第一批指南（B类)项目的通知](http://kjc.ncu.edu.cn/info/1041/2231.htm)）

### ④ 常见错误与扣分点
1. **密级留空或随手写"公开"**。快速支持模板封面第一行就是"密级:"，是必填项；且申报项目须为公开项目，**严禁涉密**——"所有申报项目均为公开项目，严禁涉密"（[江苏科技大学《关于组织申报2021年第一批快速支持项目的通知》](https://kjc.just.edu.cn/2021/0114/c9661a275336/page.htm)）。
2. **单位名称与公章不一致**。173 模板明确要求一致；形式审查要求项目建议书中的项目名称、承研单位、研究周期、项目负责人、经费匡算、项目密级**须与项目汇总表内容一致**。
3. **未脱密就直接从互联网提交**。全军武器装备采购信息网公告第十五条：公开的项目建议请从互联网网站提报，严禁填写涉密、敏感信息，并随附加盖公章的非密声明；涉密的项目建议须具备武器装备科研生产保密资格，通过涉密网系统提交。
4. **项目名称与指南方向脱节**。快速支持要求"申报项目应按照专业领域和方向自拟项目名称"（[中南大学大数据研究院转发通知](https://bdi.csu.edu.cn/info/1146/1970.htm)）。
5. **漏签、漏章**。多份转发通知都强调：项目建议书须由项目申报负责人亲自签名，并由申报单位加盖公章。

## 3. 立项依据与必要性

### ① 这一节要回答评委什么疑问
"**为什么非做不可，而且为什么现在就得做？**"
——这是军味文本里权重最高的一节。它不回答"这个技术有趣吗"，而是回答"不解决它，会卡住什么"。

### ② 必备要素清单
- [ ] 国家/军队需求牵引（上位需求：装备体系、作战任务、发展规划）
- [ ] 具体使用场景与作战使用场景描述（在什么平台、什么条件、什么任务剖面下使用）
- [ ] 装备体系贡献度：解决后能给体系带来什么能力增量
- [ ] 技术推动：技术自身演进的必然性，与前沿技术趋势的衔接
- [ ] 现实紧迫性：为什么是现在（窗口期、代差风险、卡脖子环节）
- [ ] 已有瓶颈的量化描述（现有能力 vs 目标能力的差距）
- [ ] 与本单位已有工作的衔接（不是从零开始）

### ③ 可直接套用的写法
**需求牵引段（军味，推荐模板）**：
> 随着【作战/任务样式】向【智能化/无人化/远程精确化】演进，【装备/平台】对【能力项】提出了更高要求。目前【装备/平台】在【具体环节】仍依赖【现有手段】，存在【问题1】【问题2】等制约，难以满足【具体作战任务】对【指标维度】的需求。
> 来源依据句式可参考《新时代的中国国防》对装备发展趋势的公开表述："武器装备远程精确化、智能化、隐身化、无人化趋势更加明显"、"军事安全面临技术突袭和技术代差被拉大的风险"（[《新时代的中国国防》](https://www.gov.cn/zhengce/2019-07/24/content_5414325.htm)）。

**技术推动段**：
> 近年来【技术方向】取得突破，【关键机理/新原理】为【原问题】提供了新的解决途径。将【新技术】引入【装备对象】，有望在【指标维度】上实现【量级/百分比】提升，且不改变【现有体系架构/接口】，具备工程可行性。

**必要性收束段**（一句顶三句）：
> 综上，本项目面向【上位需求】，针对【具体短板】，研究【技术名称】，形成【成果形式】，对于提升【装备体系能力项】、支撑【作战任务】具有必要性。（预期技术成熟度由 TRL【起始等级】提升至 TRL【目标等级】。）

**通用科研口径的对应句式**：
> 本项目围绕【科学问题】，针对现有【理论/方法】在【条件】下【失效/受限】的问题，开展【研究内容】，有望在【理论维度】给出【结论】。该问题的解决对【学科方向】具有基础性意义。

### ④ 常见错误与扣分点
1. **写成文献综述**，通篇"某国某学者提出了……"，没有落到"不用会怎样"。
2. **需求层级错位**：把"提升性能"当需求。军味文本里需求必须能追溯到一项**任务/装备/体系能力**，而不只是一个性能参数。
3. **只有技术推动，没有需求牵引**。军味评审对"技术自嗨"极敏感——技术再新，说不出用途就是减分。
4. **作战使用场景写得含糊**（如"可用于各类武器装备"）。快速转化模板明确要求研究背景或需求"需要明确具体的型号、背景等，写具体"。
5. **夸大必要性**：声称"填补国内空白""国际首创"却无检索或对标依据。173 模板与快速支持模板都要求填写国内外研究现状，就是用来核验这类断言。
6. **回避真实短板**：把"落后"写成"有提升空间"。国防科工局形式审查明确要求项目建议书"必要性"栏**须阐明拟解决的重大问题**（[形式审查内容及要求 第七条](https://www.sastind.gov.cn/n10086167/n10086221/c10129631/content.html)）。

## 4. 国内外研究现状与技术发展趋势

### ① 这一节要回答评委什么疑问
"你了解全局吗？你的起点在哪？你说的创新是真创新吗？"
——这一节的功能是**排除"重复研究"**，同时为第 8 节"创新点"做铺垫。项目查重是评审的固定动作：快速支持机制中，"组织责任专家进行分类整理、**项目查重**和初步筛选"是筛选流程第一步。

### ② 必备要素清单
- [ ] 国外现状与水平（按关键技术分解，不按国家罗列）
- [ ] 国内现状与水平（含本单位及国内同行）
- [ ] 对标表格：把"国外最好 / 国内最好 / 本项目目标"三列并列
- [ ] 差距的**可量化**描述（指标差值，不是"略有差距"）
- [ ] 发展趋势与技术路线之争（有哪些流派、各自瓶颈、可能收敛方向）
- [ ] 现有方案的共性不足（点出"为什么别人做不到"，即你的切入点）
- [ ] 检索范围说明（数据库、时间窗、关键词）【经验归纳，待核实】
- [ ] 若确为空白方向，模板允许简化：快速扶持（第二阶段）模板注明"如国内外未开展相关工作，可不填写"

### ③ 可直接套用的写法
**对标表模板**：

| 指标项 | 国外先进水平 | 国内现有水平 | 本项目目标 | 差距性质 |
|---|---|---|---|---|
| 【指标1】 | 【数值+出处】 | 【数值+出处】 | 【数值】 | 原理性 / 工艺性 / 集成性 |
| 【指标2】 | …… | …… | …… | …… |

**现状综述句式**：
> 在【技术方向】方面，国外自【年份】起开展【研究阶段】研究，代表性工作包括【机构/团队】的【方案名称】，其【指标】已达【数值】；主要技术路线为【路线A】与【路线B】。国内【单位】在【子方向】上取得【进展】，但在【具体环节】尚未突破，主要表现为【瓶颈描述】。

**趋势判断句式**：
> 综合国内外进展判断，【技术方向】正由【阶段A】向【阶段B】演进，核心难点集中在【难点1】【难点2】。本项目以此为切入点。

**通用科研口径句式**：
> 现有研究主要沿【路线A】【路线B】两条路径展开。A 路径【优势】，但在【条件】下【局限】；B 路径【优势】，但缺乏【某方面】的理论支撑。本项目拟从【角度】入手，弥补上述不足。

### ④ 常见错误与扣分点
1. **只写国外不写国内**：军味评审尤其关注"国内谁在做"，因为这直接关系查重与协作布局。
2. **文献罗列无归纳**：一段一个作者，读到最后不知道你的切入点在哪。
3. **用二手数据且不标出处**：所有对比数值都应有文献或报告出处，否则视为不可信。
4. **宣称"国内外均未见报道"却无检索依据**——这是评审核查的高危断言；如确无直接工作，模板允许不填，不要硬编。
5. **只有正面技术描述，回避差距**。差距写得越具体，第 8 节的创新点越立得住。

## 5. 研究目标

### ① 这一节要回答评委什么疑问
"做完之后，你到底交付了什么？达到什么状态？"

### ② 必备要素清单
- [ ] 总目标（一句话，含技术名称、装备对象、成果形态）
- [ ] 分项目标（3–5 条，每条对应一项研究内容）
- [ ] 目标的技术状态描述（即**预期达到的技术成熟度等级**）
- [ ] 与指南牵引性指标的呼应（"项目建议书在满足相应牵引性指标基础上，应提出可考核可验证的研究成果"）
- [ ] 目标的边界（不做什么，避免验收争议）

### ③ 可直接套用的写法
**总目标一句话模板**（此句式直接取自快速转化项目建议书模板的提示语）：
> 突破【××技术】，研制出【××成果】，通过【××考核】，达到【××状态或指标】，具备【××能力】，取得【××效果】，预期达到的技术成熟度等级【TRL n】。
— 来源：[快速转化项目建议书模板（全军武器装备采购信息网附件3）](http://www.weain.mil.cn/ywdt/1266418919119282178.shtml)

**分项目标模板**：
> （1）揭示【技术名称】的【机理/规律】，建立【模型/方法】，误差不大于【指标值】；
> （2）突破【关键技术名】，形成【方案/算法/样件】，在【条件】下实现【指标值】；
> （3）研制【原理样机/演示验证系统】，完成【试验项目】，通过【考核方式】，验证【能力项】；
> （4）形成【标准建议稿/专利/报告】等成果【数量】项。

**通用科研口径模板**：
> 本项目拟解决【科学问题】，具体目标为：（1）阐明【机制】；（2）建立【理论/方法体系】；（3）在【对象】上验证，性能较现有方法提升【百分比】。

### ④ 常见错误与扣分点
1. **目标写成研究内容**（"研究××算法"不是目标，"使××指标达到××"才是）。
2. **目标不可判定**：如"显著提升性能""形成一套完整技术"。快速支持模板要求"提出可考核可验证的研究成果"，含糊目标在形式上就站不住。
3. **目标超出研究期限**。173 计划技术领域基金与快速支持均有明确周期上限（173：任务周期不超过 3 年；快速扶持第一阶段原则上 6 个月内完成，第二阶段原则上 1–2 年；快速转化 1–2 年）。目标定到 5 年以后必然被砍。
4. **无技术成熟度落脚点**。快速转化模板明确要求预期达到的技术成熟度等级；国家重点研发计划也在推行技术就绪度管理（[上海交通大学科研院转发《国家重点研发计划"高端科研仪器研制"重点专项2026年度（第一批）项目申报通知》](https://keyan.sjtu.edu.cn/ky-tongzhi/20260731/6002.html)：申报指南中明确技术就绪度要求，并在后续评审立项、考核评估中纳入技术就绪度指标）。
5. **目标与指标混写**。目标回答"到哪"，指标回答"多少"，两者分节写更清楚。

## 6. 主要研究内容

### ① 这一节要回答评委什么疑问
"你要做哪些事？工作量是否匹配经费与周期？有没有漏项？"

### ② 必备要素清单
- [ ] 按技术逻辑分解的若干条研究内容（建议 3–5 条，与分项目标一一对应）
- [ ] 每条内容的内涵界定（做什么、到什么深度为止）
- [ ] 每条内容对应的**关键技术**及其内涵（快速转化模板要求"列出项目研究需解决的关键技术，简单阐述内涵"）
- [ ] 内容之间的接口关系（数据、样件、模型如何传递）
- [ ] 内容与本项目指标的映射矩阵
- [ ] 需要开展的主要试验/测试内容

### ③ 可直接套用的写法
**研究内容条目模板**：
> **研究内容【n】：【名称】**
> 内涵：针对【问题】，研究【对象/机理/方法】。
> 具体工作：（1）建立【模型】，考虑【因素】；（2）提出【方法/算法】，解决【难点】；（3）开展【试验】，验证【指标】。
> 界面：向研究内容【n+1】提供【模型/样件/数据集】，接口定义为【接口描述】。

**指标—内容映射矩阵**：

| 研究内容 \ 考核指标 | 指标1 | 指标2 | 指标3 |
|---|---|---|---|
| 内容1 | ● | ○ |  |
| 内容2 | ○ | ● | ● |
| 内容3 |  |  | ● |

（●承担主要责任，○提供支撑）

**通用科研口径的写法差异**：研究内容应围绕**科学问题**分解，而不是围绕**工程阶段**分解。即"研究【机制A】""研究【条件B】下的【行为C】"，而不是"方案设计—样机研制—试验验证"。

### ④ 常见错误与扣分点
1. **研究内容=施工流程**（"先设计、再加工、后测试"）。这不是研究内容，是工作计划；军味评审尤其反感。
2. **条数过多（7–10 条）**：内容过散意味着经费和周期分摊不足。
3. **关键技术藏在研究内容里不单列**。快速支持三套模板全部单列"关键技术"栏，B 卷更要求任务分工到关键技术级；不单列会导致后面无法做 WBS。
4. **漏掉验证类内容**。军味文本里"考核验证手段"是评审关注点——国防科工局要求申报单位须具备"考核验证手段"（[安徽工程大学科技处转发《国家国防科工局关于印发有关科研项目指南的通知》](https://kjc.ahpu.edu.cn/_t41/2025/1106/c731a258403/page.psp)）。
5. **内容与目标不闭环**：有目标无内容，或有内容不产出任何目标。

## 7. 技术途径与技术方案

### ① 这一节要回答评委什么疑问
"你凭什么认为自己能做到？路线清楚吗？可行吗？"

### ② 必备要素清单
- [ ] 总体技术方案与研究思路（先给系统级框图）
- [ ] 技术路线图（从输入到输出的完整链条，标注每一步的手段）
- [ ] 分系统/分模块方案及其选型理由
- [ ] **多方案对比与优选**（军味文本的强要求，见下）
- [ ] 理论与计算方法（公式、模型、边界条件）
- [ ] 试验/验证方案（含试验步骤）
- [ ] 采用技术的成熟度评估（哪些是成熟技术、哪些是新技术）
- [ ] 继承技术与新技术的比例
- [ ] 可行性分析（技术可行性、条件可行性、经济可行性）

### ③ 可直接套用的写法
**方案优选段**（依据《常规武器装备研制程序》第七条对《论证工作报告》内容的要求）：
> 针对【问题】，提出【方案A】【方案B】两条技术途径。方案A【原理/优点/缺点】，方案B【原理/优点/缺点】。经【对比维度：指标可达性、成熟度、周期、经费、外协依赖】综合权衡，拟采用【方案X】，理由是【理由】。
— 依据原文（《论证工作报告》的主要内容应包括）："国内外同类武器装备的现状、发展趋势及对比分析"、"主要战术技术指标要求确定的原则和主要指标计算及实现的可能性"、"初步总体技术方案论证情况"、"继承技术和新技术采用比例，关键技术的成熟程度"（[常规武器装备研制程序，论证阶段第七条](http://www.kellermen.top:2005/post/68)）【转载来源为个人博客，建议以正式渠道文本核对】

**技术路线链式写法**：
> 【输入数据/对象】→【预处理/建模（手段）】→【核心处理（本项目突破点）】→【输出/评价（指标）】→【验证（考核方式）】。

**成熟技术优先原则的表述**（可直接引用的政策依据）：
> 本项目优先采用成熟技术和通用化、系列化、组合化产品，对采用的新技术、新材料、新工艺进行充分论证、试验和鉴定，并按规定履行审批手续。
— 依据：《武器装备质量管理条例》第二十一条原文（[国务院、中央军委令第582号](https://www.gov.cn/zhengce/2010-10/08/content_2602566.htm)）

**风险前置的论证要求表述**：
> 论证结果应包含风险分析，并提出降低或者控制风险的措施；研制总体方案优先选用成熟技术，对采用的新技术和关键技术，应当经过试验或者验证。
— 依据：《武器装备质量管理条例》第十三条原文
> 论证单位应拟制多种备选的研制总体方案，并提出优选方案。
— 依据：《武器装备质量管理条例》第十四条原文

### ④ 常见错误与扣分点
1. **只给一条路线，没有比较**。军味论证要求"多方案论证—综合权衡—优选"（《常规武器装备研制程序》第六条：邀请一个或数个持证单位进行多方案论证），单方案论证会被视为论证深度不足。
2. **无框图、无流程图**：技术方案是图形化表达最密集的一节，纯文字描述会被判定"论证不深入"。
3. **"卡脖子"环节不标注**：关键技术中哪些依赖外协、哪些依赖进口器件，必须标明并给出替代方案。
4. **试验方案缺失或空洞**："通过仿真和试验验证"不是试验方案；快速转化模板要求考核方式明确"考核实施单位（具有相关测试评价资质的第三方、武器装备研制总体单位或承研方自测）、考核环境、考核方法、考核依据（标准）、考核指标"。
5. **新技术/成熟技术比例不明**。这是《论证工作报告》的必备项，也是评审判断风险的主要抓手。

## 8. 关键技术与创新点

### ① 这一节要回答评委什么疑问
"难点在哪？你解决了什么别人没解决的？"

### ② 必备要素清单
- [ ] 关键技术清单（每条含：名称、内涵、难点所在、拟采取的解决途径、风险等级）
- [ ] 关键技术对应的攻关手段（理论推导 / 仿真 / 试验 / 原理样件验证）
- [ ] 创新点清单（3 条以内，宁少勿滥）
- [ ] 每个创新点的**创新类型**标注：新原理 / 新方法 / 新结构 / 新工艺 / 新集成
- [ ] 每个创新点的**对比锚点**（与谁比、在哪一点上不同）
- [ ] 创新点的可验证性（怎么证明这个创新是成立的）
- [ ] 拟解决的关键科学问题（173 模板要求单列此项）

### ③ 可直接套用的写法
**关键技术条目模板**：
> **关键技术【n】：【名称】**
> 内涵：【一句话定义】
> 难点：在【条件】下，【因素】导致【问题】，现有方法【局限】。
> 解决途径：采用【方法】，通过【手段1】【手段2】实现。
> 风险等级：高/中/低；备选方案：【备选】。

**创新点条目模板**：
> **创新点【n】**：首次将【方法/原理】应用于【对象】，实现【效果】。与【对比对象】相比，在【维度】上【差异描述】。佐证方式：【仿真对比/试验数据/专利检索】。

**关键科学问题模板**（173 模板专设栏目）：
> 拟解决的关键科学问题：【问题陈述，应是一个尚无定论的科学问题，而非工程难题】。

**快速支持模板的特色要求**（创新性论证的原文标准）：
> 创新性要求：①是以申请者本人、本团队为主提出的原创性想法；②允许在其他研究课题基础上再创新，但申请书中必须说明，尤其是与前者的区别和再创新增量。
> 颠覆性潜力要求：①应有抢占科技制高点的潜力，或者有可能探索出实现创新超越的新途径；②针对集成创新的申请，应基于相关领域的最新技术成果，集成后具有重大军事应用潜力；③针对未来作战概念创新的申请，应突出理技结合，强调基于对技术发展的预测预判，可能带来作战样式的变革等。
— 原文来源：[桂林理工大学南宁分校科技管理部《转发国防科技创新特区加快对创新探索研究进行支持的通知》](https://nnfx.glut.edu.cn/kjglb/info/1009/1079.htm)（该通知转述国防科技创新特区对"火花课题"的申请条件）

### ④ 常见错误与扣分点
1. **创新点写成本项目工作内容**（"研究了××系统"不是创新点）。
2. **创新点数量虚高**：写 6–8 条，每条都是"首次提出"，反而暴露没有真创新。
3. **创新点无对比锚点**："提出了一种新方法"——新在哪？和谁比？
4. **混淆关键技术与创新点**：关键技术是"难点"，创新点是"新增量"，不是一回事。
5. **在已有课题基础上再创新却不说明增量**：创新特区的申请条件明确要求说明"与前者的区别和再创新增量"；这是被直接点名的失分项。
6. **把"首次在国内实现"写成"国际首创"**：需要检索支撑，否则属于不实陈述。科研诚信要求已写入各类申报通知（如"杜绝夸大不实，严禁弄虚作假"，见[上海交通大学科研院转发通知](https://keyan.sjtu.edu.cn/ky-tongzhi/20260731/6002.html)）。

## 9. 已有研究基础与条件

### ① 这一节要回答评委什么疑问
"你凭什么做得出来？团队、平台、前期积累够不够？"

### ② 必备要素清单
- [ ] 单位简要情况（性质、资质、相关领域地位）
- [ ] 研究基础：与本项目直接相关的**前期工作**（973/预研/基金项目、已完成样机、已验证的结论）
- [ ] 代表性成果（论文/专利/软著/标准/获奖/样机），173 模板要求"选取代表性5项"
- [ ] 实验条件与平台（实验室、装置、测试能力、计算资源）
- [ ] 项目负责人概况（教育背景、主要研究方向、代表性成果、在研项目情况）
- [ ] 主要参加人员表（姓名、出生年月、职务/职称、单位、分工、年工作量）
- [ ] 与本项目相关的**在研项目及关系说明**（173 模板要求填写"正在承担的相关科研计划项目情况"及"与本单位相关科研项目的关系""与团队成员已知的其他科研计划已安排项目的关系"）
- [ ] 外协条件（快速转化模板要求：列举需外协的单位名称、原因、各单位负责内容）
- [ ] 管理与保障措施

### ③ 可直接套用的写法
**代表性成果条目**（173 模板提示：选取代表性 5 项，简要说明目标成果/论文/专利/专著等，并简述成果的发展效益、学术贡献和创新之处，每项不超过 120 字）：
> 【成果名称】（【年份】）——【一句话说明成果内容与水平】，【对本项目的支撑作用】。

**在研项目关系说明模板**：
> （1）与本单位相关科研项目的关系：本单位承担的【项目名称】（【来源/编号，如可公开】）研究【内容】，与本项目在【衔接点】上互补/不重复，本项目在其基础上进一步【增量】。
> （2）与团队成员已安排项目的关系：团队成员【姓名】承担的【项目名称】拟解决【问题】，与本项目在【技术环节】上互为支撑，研究内容无重复。

**外协—主承研单位分工的清晰化写法**（形式审查的硬性要求）：
> 联合承研单位【名称】承担【任务】，申请经费【×××】万元；各单位经费之和与项目总经费一致。
— 依据：《国防科工局技术基础科研项目建议书形式审查内容及要求》第十条："联合承研的科研项目，项目建议书'主要技术人员'栏须明确联合承研单位参研人员，'联合承研单位'栏须明确联合承研单位承担的任务，'经费匡算'栏须明确联合承研单位申请的经费，各单位经费之和须与项目总经费一致。"（[原文](https://www.sastind.gov.cn/n10086167/n10086221/c10129631/content.html)）

**资质合规的必备声明**：
> 本项目主承研单位具备独立法人资格，并具备与项目密级相应的保密资质。
— 依据：同文件第九条："科研项目承研单位须具备独立法人资格，以及与项目密级相应的保密资质，项目建议书'科研项目基本信息表'中须如实填写（主）承研单位具备的资质。"

### ④ 常见错误与扣分点
1. **研究基础与研究内容不相关**：拿一堆无关论文充数，评审一眼看穿。
2. **成果罗列无支撑作用说明**：173 模板要求"简述成果的发展效益、学术贡献和创新之处"，只说标题不说作用。
3. **不填在研项目情况**：这直接关系到**限项**与**重复申报**——快速支持规定"同一年度以同一申请人身份申请或在研的项目不得超过三项"；国家重点研发计划的限项要求更严（项目骨干的申报项目和改革前计划、国家重大科技专项、国家重点研发计划在研项目总数不得超过 2 个，见[科技部关于填报国家重点研发计划"ECMO系统研发"项目申报书的通知](https://www.most.gov.cn/tztg/202009/t20200916_158773.html)）。
4. **人员表缺年工作量**：快速支持第二阶段与快速转化模板的人员表均含"年工作量"列；173 计划则对负责人有"每年度投入项目工作时间不低于 6 个月"的要求（[南昌大学转发通知](http://kjc.ncu.edu.cn/info/1041/2231.htm)）。
5. **外协单位与经费对不上**：形式审查会直接卡掉。
6. **团队组合与任务不匹配**：无验证/测试人员，或无工程实现人员。

## 10. 技术指标与考核方式

### ① 这一节要回答评委什么疑问
"你说的成功，用什么尺子量？谁来量？"

### ② 必备要素清单
- [ ] 指标条目化：编号、名称、数值、单位、**测试条件**、判定准则
- [ ] 牵引性指标 vs 自提指标的区分（指南有牵引性指标时须先满足）
- [ ] 考核方式：考核实施单位、考核环境、考核方法、考核依据（标准）、考核指标
- [ ] 测试/试验大纲要点
- [ ] 仿真与实测的关系与可信度说明
- [ ] 指标与阶段对应关系（哪个阶段验证到哪一项）

### ③ 可直接套用的写法
**指标条目化模板**（军味/通用通用）：

| 序号 | 指标名称 | 指标值 | 单位 | 测试条件/状态 | 判定准则 | 考核方式 | 验证阶段 |
|---|---|---|---|---|---|---|---|
| 1 | 【指标1】 | ≥【数值】 | 【单位】 | 在【温度/工况/样本量】下 | 全部【n】组合格 | 第三方测试 | 第二阶段末 |
| 2 | …… |  |  |  |  |  |  |

**考核方式段模板**（直接取自快速转化项目建议书模板的提示语）：
> 明确该项成果的考核方式，包括考核实施单位（具有相关测试评价资质的第三方、武器装备研制总体单位或承研方自测）、考核环境、考核方法、考核依据（标准）、考核指标等。
> 考核项目应全面覆盖所列项目关键问题、项目技术指标、项目主要成果。考核方式应与技术成熟度等级要求一致。
— 来源：[快速转化项目建议书模板](http://www.weain.mil.cn/ywdt/1266418919119282178.shtml)

**通用科研口径的写法差异**：不写"判定准则"，写"评价指标与验证方法"，且允许以理论证明、数值实验作为验证手段。

### ④ 常见错误与扣分点
1. **指标无测试条件**："精度优于 1 m"——在什么距离、什么条件下？无条件的指标在验收时无法判定。装备预研类评审对此极其敏感。
2. **指标与考核方式脱钩**：写了指标却没写怎么测。
3. **坑指标**（定得过高无法达成）：快速扶持项目虽规定"对已履行勤勉尽责义务，但由于技术未知难度等客观原因难以完成预定目标的，经综合评估确认后，不追究责任"，但同时规定"对未履行勤勉尽责义务的……列入'黑名单'……三年内不得申报预研共用技术领域项目"（[全军武器装备采购信息网公告第14条](http://www.weain.mil.cn/ywdt/1266418919119282178.shtml)）。
4. **漏写牵引性指标**：173 计划要求"项目建议书在满足相应牵引性指标基础上，应提出可考核可验证的研究成果"（[南昌大学转发通知](http://kjc.ncu.edu.cn/info/1041/2231.htm)）。
5. **考核方式全填"承研方自测"**：对关键指标应安排第三方测试或总体单位考核，自测仅适用于初期阶段。

## 11. 进度计划与里程碑

### ① 这一节要回答评委什么疑问
"这点时间够不够？中途怎么知道你做到哪了？"

### ② 必备要素清单
- [ ] 总周期与阶段划分（阶段数、各阶段起止）
- [ ] 进度表：年度 | 主要完成内容和技术指标 | 完成标志 | 备注
- [ ] 里程碑节点与交付物
- [ ] 各阶段的转阶段条件（转阶段评审依据）
- [ ] 关键路径与外部依赖（外协进度、设备采购、试验窗口）

### ③ 可直接套用的写法
**进度表模板**（表结构与列名直接取自快速扶持（第二阶段）与快速转化项目建议书模板的"进度安排"表）：

| 年度/阶段 | 主要完成内容和技术指标 | 完成标志 | 备注 |
|---|---|---|---|
| 第1年 | 【内容】，实现【指标】 | 如通过测试、试车、评估等；或标志性成果 | 【外部依赖】 |
| 第2年 | 【内容】，实现【指标】 | 【标志性成果】 |  |

**转阶段条件表述**（可引用的政策依据）：
> 每个阶段的工作按规定的要求完成后，方可转入下一阶段。军队有关装备部门按武器装备研制程序组织转阶段审查，确认达到规定的质量要求后，方可批准转入下一研制阶段。
— 依据：《常规武器装备研制程序》第四条（[原文](http://www.kellermen.top:2005/post/68)）；《武器装备质量管理条例》第二十五条（[原文](https://www.gov.cn/zhengce/2010-10/08/content_2602566.htm)）

**周期上限的合规提醒**（写进度前先核对这些公开规则）：
- 173 计划技术领域基金：任务周期不超过 3 年；重点项目经费 200–300 万，一般项目 100 万以下；单个项目支持额度从数十万到 300 万（[南昌大学](http://kjc.ncu.edu.cn/info/1041/2231.htm)、[江苏科技大学](https://kjc.just.edu.cn/2021/0303/c9661a276660/page.htm)）。
- 快速扶持第一阶段：原则上 6 个月内完成；第二阶段：原则上 1–2 年；快速转化：1–2 年（[全军武器装备采购信息网公告](http://www.weain.mil.cn/ywdt/1266418919119282178.shtml)）。

### ④ 常见错误与扣分点
1. **进度表只有年份没有"完成标志"**：模板专设"完成标志"列，就是要求每阶段有可验证的产出。
2. **阶段划分与研究内容不对应**。
3. **无里程碑考核节点**：快速扶持项目"不组织审价、不设中间考核节点"，但快速转化项目"可设一个中间考核节点"——是否设节点由项目类别决定，别写反。
4. **时间安排不留余量**：试验窗口、外协交付、评审排队都要留缓冲。

### ② 必备要素清单
- [ ] 总经费（申请经费 + 自筹/配套经费）
- [ ] 按科目分解（科目名称必须使用指南/模板的规定口径）

- [ ] 每个科目的测算依据与说明
- [ ] 联合承研单位的经费划分
- [ ] 配套经费来源与用途说明

### ③ 可直接套用的写法
**经费科目口径（军口，173 模板附件1 与快速转化模板的预算科目）**：

| 173 模板科目（直接费用） | 装备预研快速支持模板科目 |

| 5. 会议/差旅/国际合作与交流费 | 5. 事务费 |

| 7. 劳务费 | 7. 管理费 |
| 8. 专家咨询费 | 8. 工资及劳务费 |
| 9. 其他支出 | 9. 收益 |
| （间接费用）10. 绩效支出/间接绩效支出 | 10. 不可预见费 |

— 来源：173 模板附件1"项目经费概算说明"逐条科目（[下载文件](https://kjc.just.edu.cn/2021/0303/c9661a276660/page.htm)）；快速转化项目建议书模板"年度经费概算"表（[附件3](http://www.weain.mil.cn/ywdt/1266418919119282178.shtml)）

**必填的经费口径声明**（173 模板的写法）：
> 分年段列出总经费×万元，其中自筹经费×万元；研究期限根据实际情况填写（不超过3年）。

**快速转化的经费概算写法**（模板提示原文）：
> 该项目总经费***万元，申请装发计划支持***万元，单位自筹配套经费***万元。
> 本部分只分解申请装发计划支持的经费。（按研究内容分解 + 按年度分解）

**可引用的经费比例硬约束（军口）**：
> 管理费不得超过项目成本总额的 8%，子项目经费之和须与总经费一致。
— 依据：《国防科工局技术基础科研项目建议书形式审查内容及要求》第八条（[原文](https://www.sastind.gov.cn/n10086167/n10086221/c10129631/content.html)）

**可引用的经费比例（军民口）**：
> 项目国拨经费不超过项目总经费的 70%。
— 依据：国家国防科工局 2025 年 10 月有关科研项目指南通知（[安徽工程大学科技处转发](https://kjc.ahpu.edu.cn/_t41/2025/1106/c731a258403/page.psp)）

**可引用的经费测算原则（民口）**：
> 按照"目标相关性、政策相符性和经济合理性"的原则，科学合理、实事求是地进行编制。每个项目设定专项经费指导数，正式申报项目专项经费预算不得高于经费指导数。直接费用各科目预算均无比例限制。
— 依据：《科技部关于填报国家重点研发计划"ECMO系统研发"项目申报书（含预算申报书）的通知》（[原文](https://www.most.gov.cn/tztg/202009/t20200916_158773.html)）

### ④ 常见错误与扣分点
1. **科目口径用错**：军口项目套用民口"直接费用/间接费用"口径，或反之。**先看模板给的表头，再改内容**。
2. **经费与预算指导数冲突**：国家重点研发计划明确"正式申报项目专项经费预算不得高于经费指导数"。
3. **联合承研单位经费之和不等于总经费**——形式审查直接判不通过。
4. **管理费超 8%**（国防科工局类项目）。
5. **"经费匡算"栏未由财务主管领导签名**：形式审查第六条明确要求经费匡算栏须由主承研单位财务主管领导签名；"承研单位诚信承诺"栏须由主要领导签名并加盖公章（[原文](https://www.sastind.gov.cn/n10086167/n10086221/c10129631/content.html)）。
6. **自筹配套金额未提供来源证明**：明确有配套经费的项目应出具自筹经费来源证明并明确配套金额（[科技部通知](https://www.most.gov.cn/tztg/202009/t20200916_158773.html)）。
7. **经费概算与研究内容脱节**：每个大额科目都要能对应到某条研究内容。

## 13. 风险分析与对策

### ① 这一节要回答评委什么疑问
"你想到过会失败吗？失败了怎么办？"

### ② 必备要素清单

- [ ] 进度风险（外协、试验窗口、人员变动）

- [ ] 经费风险（配套不到位、涨价）
- [ ] 军方/用户接口风险（数据、场景、接口条件不能及时到位）
- [ ] 每一项风险的**等级**（高/中/低）、**触发条件**、**应对措施**、**责任人**
- [ ] 备选技术途径（Plan B）

### ③ 可直接套用的写法
**风险表模板**：

| 序号 | 风险类别 | 风险描述 | 触发条件 | 等级 | 应对措施 | 备选途径 |
|---|---|---|---|---|---|---|
| 1 | 技术 | 【关键技术】在【条件】下可能达不到【指标】 | 【触发条件】 | 高/中/低 | 【措施】 | 【Plan B】 |
| 2 | 进度 | 【外协单位】交付延迟 | 【触发条件】 | 中 | 【措施】 | 【Plan B】 |

**政策依据式表述**（把风险分析写成"按规范执行"而非"我承诺小心"）：
> 按武器装备论证质量管理要求，论证单位应对论证结果进行风险分析，提出降低或者控制风险的措施；对采用的新技术和关键技术，应当经过试验或者验证。
— 依据：《武器装备质量管理条例》第十三条、第十五条（[原文](https://www.gov.cn/zhengce/2010-10/08/content_2602566.htm)）

**免责条款的正确使用**（快速扶持项目特色）：
> 对已履行勤勉尽责义务，但由于技术未知难度等客观原因难以完成预定目标的，经综合评估确认后，不追究责任。
— 但须注意反向约束：对未履行勤勉尽责义务的，一经查实将严肃追究承研团队和所属单位责任，列入"黑名单"，并在全军武器装备采购信息网通报，三年内不得申报预研共用技术领域项目（[全军武器装备采购信息网公告第14条](http://www.weain.mil.cn/ywdt/1266418919119282178.shtml)）。

### ④ 常见错误与扣分点
1. **风险写成"无明显风险"**——这是最常见的硬伤，等于宣布没有认真论证。
2. **有风险无措施**，或有措施无责任人。
3. **只写技术风险**：进度、配套、外协风险同样被看。
4. **把"经费充足"当风险对策**。
5. **Plan B 与主方案实质相同**（只是换了表述）。

## 14. 预期成果与效益

### ① 这一节要回答评委什么疑问
"这些东西最终去哪儿？能给体系带来什么？"

### ② 必备要素清单
- [ ] 成果清单与形式（原理样机/演示验证系统/方法库/软件/标准建议稿/专利/论文/报告）
- [ ] 成果数量与技术状态（对应 TRL 等级）
- [ ] 应用前景：直接应用对象（型号/装备/平台）
- [ ] 军事效益（能力提升、体系贡献度）
- [ ] 经济效益（若有民用转化）
- [ ] 科学价值/学术贡献（通用科研口径的主项）
- [ ] 成果的**可用性、好用性、耐用性**论述（军工口近年强调的表述）

### ③ 可直接套用的写法
**成果条目模板**：
> **成果【n】：【名称】**
> 形式：【原理样机/算法包/标准建议稿/发明专利】
> 状态：预期达到 TRL【n】
> 应用去向：【型号/装备/平台】，由【应用单位】接续开展【工作】
> 效益：可【能力提升描述】，预计【量级描述】

**成果可用性表述**（可直接借鉴的政策语言）：
> 突出攻关成果在军工科研生产中的实际应用效果，对研制的设备仪器指标进行全面考核验证，开展试用或应用，促进攻关成果能用、好用、耐用。
— 依据：国家国防科工局 2025 年 10 月有关科研项目指南通知（[安徽工程大学科技处转发](https://kjc.ahpu.edu.cn/_t41/2025/1106/c731a258403/page.psp)）

**成果转化通道表述**（快速支持类项目可引用的政策原文）：
> 通过评审验收达到优秀标准的快速扶持项目，按程序报批后，成果直接转入相关渠道安排实施。通过评审验收达到优秀标准的快速转化项目，成果定期向相关单位推荐使用。
— 依据：《关于建立装备预研共用技术领域基金类项目快速支持机制（试行）的公告》第四部分第13条（[原文](http://www.weain.mil.cn/ywdt/1266418919119282178.shtml)）

**通用科研口径的写法差异**：把"军事效益"替换为"科学价值/学术贡献"，把"应用去向"替换为"理论意义与推广前景"。

### ④ 常见错误与扣分点
1. **成果清单与指标/内容不对应**：有指标却没有对应的支撑成果。
2. **只写论文专利**：军味项目若只交付论文和专利，会被质疑"不落地"。
3. **应用前景写虚**："可用于航空航天、船舶、能源等广泛领域"——领域越广，越说明没想清楚。
4. **无技术成熟度落脚**：快速转化模板明确要求写"预期达到的技术成熟度等级"。
5. **不写成果去向的"下一个接手方"**：军工项目的成果必须有接续渠道（型号、预研后续、转化渠道）。

## 15. 参考文献

### ① 这一节要回答评委什么疑问
"你引的东西是真的吗？"

### ② 必备要素清单
- [ ] 国内外文献（近 3–5 年为主）
- [ ] 标准与规范（GJB、GB、行业标准）
- [ ] 政策与规划文件（可公开的）
- [ ] 专利文献（含国防专利检索说明）
- [ ] 每条文献的可核验标识（作者、题目、出处、年份、DOI/标准号）
- [ ] 引用一致性（正文引用与文末条目一一对应）

### ③ 可直接套用的写法
> [1] 【作者】. 【题名】[类型标识]. 【出处】, 【年份】, 【卷(期)】: 【页码】. DOI:【doi】
> [2] GJB 7688-2012 装备技术成熟度等级划分及定义[S].

**引用规范提示**：国防专利检索有专门渠道，国防专利是指涉及国防利益以及对国防建设具有潜在作用需要保密的发明专利（[《国防专利条例》第二条](https://www.cnipa.gov.cn/art/2015/9/8/art_98_28198.html)）。涉及国防专利的检索与引用，应通过单位保密渠道核实。

### ④ 常见错误与扣分点
1. **正文引用与参考文献不对应**。
2. **引用不可核验的来源**（无出处的"内部资料"、无编号的"某报告"）。
3. **引用非公开文件**：涉密文件、内部指南不得作为参考文献出现。
4. **文献过时**：全部是 5–10 年前的文献，会被质疑不了解现在。
5. **标准号写错**。这类错误在军口文本里极为显眼，务必核对。

## 19. 安全保密专篇（2026 回标补充 · 现行必备栏目）

> ⚠️ **本项为 136 号（2010）七项之外的现行新增必备论证内容**：依 **科工技〔2026〕112 号 第二十条(一)**（建议书阶段）明文，「**安全保密专篇**」被列入论证内容；**科工技〔2010〕136 号 第二十六条**的七项（必要性／现有的研究基础／研究目标／主要研究内容／研究周期／研究经费匡算／预期成果）**未包含本项**。依据：[科工技〔2026〕112号 第二十条(一)、第二十一条(一)](https://www7.zzu.edu.cn/jg/info/1057/1122.htm)；[136号 第二十六条](https://www.sastind.gov.cn/n10086167/n10086221/c10129558/content.html)
>
> **本节只停在公开可讨论的方法论层面**（这一节要写哪些栏目、怎么组织）。**具体的涉密事项、密级判定结论、定密依据原文、保密资格等级与保密制度文本，一律不在公开文本中展开**，由承研单位保密工作机构在**涉密渠道**内确定与出具。**本骨架不列举任何涉密事项清单，不推测任何密级判定实务。**

### ① 这一节要回答评委什么疑问
1. **这个项目要不要按保密管理？依据是什么？**——不是「我们觉得不涉密」，而是有定密程序、有书面结论。
2. **谁来管？条件够不够？**——承研单位应具备的条件与项目密级是否匹配、项目负责人是否符合资格要求。
3. **从头到尾有哪些环节要管？**——立项、研发、试验、外协、数据与载体、发表与宣传、结题与成果处置。
4. **走公开路径时，凭什么可以按非密报送？**——非密证明/非密声明的出具链条与留存。
5. **谁检查、出了问题谁负责？**——检查频次、检查内容与责任主体。

### ② 必备要素清单
- [ ] **保密工作组织与责任人**：单位保密工作机构、项目组保密责任人、岗位职责（**只写组织与职责，不写具体人员涉密信息**）
- [ ] **条件与资格匹配性说明**：承研单位应具备的条件、项目负责人与参与人员的资格要求（依据见 ③）
- [ ] **项目密级结论与定密依据的出具方式**：写明「密级结论与定密依据由承研单位保密工作机构按国家保密法律法规及本单位定密权限确定/报批，在涉密渠道另行出具」——公开正文只写**程序与出处**，不写结论内容
- [ ] **全周期保密管理环节梳理（框架级）**：立项报批 → 研发与试验 → 数据与载体 → 外协与协作 → 发表与宣传 → 结题与成果处置（逐环节写「**管什么、按哪一类制度管**」，不写具体事项）
- [ ] **涉密载体与信息系统管理（制度性表述）**：载体的制发、传递、使用、复制、保存、维修、销毁的审批链条与登记留痕；涉密计算机与存储介质不得连接互联网及其他公共信息网络
- [ ] **人员管理**：涉密岗位管理、岗前保密教育、在岗与离岗（调岗、离职、退休、借调）手续、外来与临时人员接触范围限制
- [ ] **外协与协作保密要求**：外协/分包立项前核验承接方条件、签订专项保密协议、明确接触面与泄密责任
- [ ] **发表与宣传审查程序**：论文、专利、会议报告、学位论文、宣传报道与参展**先审后发**
- [ ] **涉外交流保密审查**：出国（境）、国际会议、境外合作与参展的审批
- [ ] **解密与密级变更程序**：项目结束、成果处置或范围变化时的密级调整与解密审批
- [ ] **保密检查与责任追究**：自查频次、配合上级检查、问题整改与责任清单
- [ ] **公开（非密）申报路径下的附加件**：单位保密部门出具的**非密证明/非密声明**（盖章 PDF）与脱密处理说明

### ③ 可直接套用的写法
**（a）条件要求的法定句式（136 号，可直接引用）**
> 承研单位是项目实施的责任主体，应**具备法人资格和保密资质**。多个单位联合承担研究任务的，**主承研单位**为项目牵头责任单位。
> — 依据：科工技〔2010〕136号 第十二条（[原文](https://www.sastind.gov.cn/n10086167/n10086221/c10129558/content.html)）；另见同办法第九条「国防基础科研项目管理按照**保密管理的有关法律法规**执行」

**（b）现行总纲句式（112 号，可直接引用）**
> 涉密科研项目严格执行保密管理有关规定。**承担有保密要求科研项目的单位，应具有相应资质。**
> — 依据：科工技〔2026〕112号 第十条（[原文](https://www7.zzu.edu.cn/jg/info/1057/1122.htm)）；任务书侧同类要求见第二十一条(一)（含「**安全保密专篇**」）

**（c）申报路径与递送方式（体系级口径，可直接引用）**
- 公开路径：指南在互联网端发布，**不要求**保密资质，常见需附单位保密部门出具的**非密证明/非密声明**，材料在互联网端在线报送。
- 涉密路径：指南「**定向**」发布，或到指定场所现场查阅；必须具有与项目密级相应的保密资质，**否则不予受理**；材料由**专人送往或机要邮寄**，不得经普通邮政、快递或互联网传输。
> — 依据：112号第十七条（分级分类发布）；[大连理工大学《关于进一步规范国防科研项目申报过程保密管理的通知》](http://scidep.dlut.edu.cn/info/1070/23008.htm)

**（d）专篇开头的「边界声明」模板（避免把涉密内容写进公开稿）**
> 本项目安全保密工作按国家保密法律法规与本单位保密管理规定执行。**项目密级结论、定密依据及具体保密事项，由承研单位保密工作机构在涉密渠道内确定与出具**；本专篇仅陈述保密工作组织、责任分工与管理措施安排。

**（e）组织与责任句式模板**
> 本项目保密工作由〔单位〕保密工作委员会统一领导，〔保密办〕负责日常监督检查；项目组设保密责任人〔岗位〕，负责本项目保密要求的组织落实与自查。项目组全体成员上岗前接受保密教育并签署保密承诺，人员变动时按离岗保密管理规定办理交接与清退手续。

**（f）外协与协作句式模板**
> 本项目外协〔拟外协的环节类别〕。外协前由〔单位〕核验承接单位相应条件，签订专项保密协议，明确保密范围、接触人员、成果归属与泄密责任；外协内容的管理要求不得高于本单位在本项目中的相应权限。

**（g）发表与宣传句式模板**
> 项目组成员对外发表论文、申请专利、参加学术会议、公开宣传报道及研究生学位论文，均须按「**先审查、后公开**」程序报〔单位保密工作机构〕审查批准，未经批准不得对外提供本项目任何技术资料与数据。

**（h）检查与责任句式模板**
> 项目组每〔季度/半年〕开展一次保密自查，配合上级与本单位保密检查，对检查发现的问题限期整改；违反保密规定的，按本单位保密管理制度与国家有关规定追究责任。

### ④ 常见错误与扣分点
1. **封面写了密级就当成「交了这一节」**——112 号第二十条(一)要的是**专篇论证**，不是密级标注。
2. **整节缺失**：只按 136 号七项搭骨架，文本里根本没有这一节；这是**形式审查／初审阶段最容易被退回的漏项**。
3. **定密依据不明**：写「本项目不涉密」或只给一个密级结论，却不交代**结论由谁按什么程序出具**。公开稿应写**程序与出处**，不写结论内容。
4. **把不该写的写进公开稿**：一旦把只能来自内部指南或内部部署的参数、需求来源写进公开材料，问题性质就远超「文本质量不合规」。
5. **漏外协单位的保密要求**：反无人机类项目常见多单位联合与配套外协，外协正是泄密风险与责任断点。
6. **漏发表审查程序**：论文、会议投稿、学位论文与宣传报道是高风险口，必须写「先审后发」。
7. **没有解密／密级变更条款**：项目结束或成果处置时无从办理。
8. **条件与密级不匹配**：涉密路径下「**不予受理**」是明文后果，不要指望事后补。
9. **材料走错通道**：涉密材料由专人送往或机要邮寄，不得经互联网或普通快递提交。

## 20. 科学数据管理计划（2026 回标补充 · 现行必备栏目）

> ⚠️ **本项同为 136 号（2010）七项之外的现行新增必备论证内容**：**科工技〔2026〕112 号 第二十条(一)（建议书）与第二十一条(一)（任务书）**均明文列入「**科学数据管理计划**」；**两阶段论证内容不等同，不得合并引用**（任务书侧第二十一条(一)另含任务分工、经费概算、安全保密专篇、关键节点标志性成果与考核方式等）。依据：[科工技〔2026〕112号 第二十条(一)、第二十一条(一)](https://www7.zzu.edu.cn/jg/info/1057/1122.htm)；[136号 第二十六条](https://www.sastind.gov.cn/n10086167/n10086221/c10129558/content.html)

### ① 这一节要回答评委什么疑问
1. **项目会产生哪些数据？**（种类、来源、规模量级，逐项列）
2. **数据怎么保证质量与可用？**（采集规程、元数据、标注与校验）
3. **数据放在哪、谁负责？**（存储位置、备份、数据责任人与管理岗位）
4. **谁能用、怎么共享？**（开放条件、审批流程、使用约定）
5. **公开数据与需保密管理的数据怎么隔离？**（分级分类与分渠道，不与安全保密专篇的涉密内容混写）
6. **项目结束后数据去哪？**（保留、汇交、移交或销毁）

### ② 必备要素清单
- [ ] **数据清单与分类**：试验/实测数据、仿真数据、算法模型与参数、软件与数据集、标注样本等（按**类别**列，不写具体指标值）
- [ ] **采集与质量控制**：采集规程、仪器与工况记录、重复试验与校验方法、异常数据处理规则
- [ ] **元数据与文档规范**：数据集名称、时间、环境条件、单位、字段定义、版本号——**没有元数据的数据集不可复用，评审不易认可**
- [ ] **存储、备份与保存期限**：存放位置（单位平台／服务器）、备份频率与介质、保存期限、介质更换与迁移
- [ ] **分级分类与隔离要求**：按单位与国家有关规定分级分类；**公开数据与需保密管理的数据不得混存、混用同一平台**（需保密管理的数据按保密渠道执行，不在公开稿展开）
- [ ] **共享与使用审批**：对外提供／共享的条件、审批层级、使用协议与引用要求
- [ ] **汇交安排**：向单位数据管理平台或指定数据机构汇交的**对象、时限、形式**（按当年指南与本单位数据管理规定执行）
- [ ] **数据责任人**：数据管理员／项目负责人职责与交接
- [ ] **数据知识产权与成果标注**：数据集作为成果形式时的归属、引用与标注方式（与 §14 预期成果、§12 经费中的数据处理支出对齐）
- [ ] **项目结束后的处置**：保留、移交、开放或销毁的决定程序
- [ ] **变更程序**：数据管理方案变更的审批与备案

### ③ 可直接套用的写法
**（a）法定依据句式（可直接引用）**
> 项目建议书（第二十条(一)）与项目任务书（第二十一条(一)）的论证内容均包含「**科学数据管理计划**」。
> — 依据：科工技〔2026〕112号 第二十条(一)、第二十一条(一)（[原文](https://www7.zzu.edu.cn/jg/info/1057/1122.htm)）

**（b）总体原则句式模板**
> 本项目科学数据管理遵循「**谁产生、谁负责；分级分类、安全可控；能用可查、应存尽存**」的原则，由项目负责人对数据质量与安全负总责，设数据管理员〔岗位〕负责日常管理。

**（c）数据清单句式模板（表格化最省事）**
> 【建议用一张表一次说清】数据类别 ｜ 产生环节（对应研究内容） ｜ 规模量级 ｜ 存储位置 ｜ 责任人 ｜ 是否对外共享

**（d）质量与元数据句式模板**
> 每类数据在采集时同步记录〔试验条件／设备型号与编号／环境参数／采样率／时间戳〕等元数据，字段定义与单位按〔本单位数据规范／项目数据字典〕执行；数据入库前经〔自检 + 复核〕两级校验，不合格数据标记留痕，不得覆盖原始记录。

**（e）隔离与共享句式模板**
> 项目数据按〔单位数据分级分类规定〕分级管理；**对外发布、共享或汇交的数据须经〔项目负责人 + 单位数据／保密管理部门〕审查批准**；需按保密管理的数据按保密管理规定在相应渠道内存储与使用，**不进入对外共享库**。

**（f）与考核节点绑定的句式模板（建议书阶段就要为 B 卷留接口）**
> 本项目数据集与配套说明文档作为〔阶段／节点〕的交付物之一，在〔节点名称〕时按〔形式〕提交并接受考核；数据管理计划的执行情况纳入项目自查范围。

### ④ 常见错误与扣分点
1. **整节缺失**——112 号明文要求；且它与安全保密专篇是**两节并列**的关系，把两者合成一节写会同时丢两项。
2. **写成「数据保密说明」**：科学数据管理计划回答的是**数据全生命周期管理**，不是保密制度的复述。
3. **只写「数据量大、很重要」**：没有数据清单与责任人，不可考核。
4. **没有元数据与采集规程**：数据不可复用，成果形态里的「数据库／数据集」落不了地。
5. **项目结束后数据去向不明**：无人负责、无法追溯。
6. **公开数据与需保密管理的数据混存同一平台**：这是**风险等级最高的写法**，公开稿必须写明「隔离／分渠道」。
7. **数据集不作为交付物、不进考核节点**：A 卷写下的成果必须在 B 卷可考核；数据集写了却不绑定节点，任务书阶段会被迫返工。
8. **汇交对象、时限、形式不写**：只写「按规定汇交」等于没写。
