# 军工/国家级科研项目书撰写

## 1. 文体与格式铁律（以真实申报件为准）—— 最高优先级

> **这一节压过本文件其他一切写法建议。** 依据：`references/09-真实申报件写作与格式拆解.md`（源自主源 `_ref/凌霄.txt`，真实申报书《基于舰船红外尾迹的快速检测与态势识别技术》，1,004 行 / 44,864 字符，全文实测）与辅源国重研发申报书（**文本层损坏，仅结构可信**）。

### 1.1 铁律 · 正文禁止出现（出现即不合格，逐条核查）

**正文是一份「已经想清楚了的方案」，不是「一份正在整理的工作稿」。** 以下 11 类元信息**一律不得出现在正文里**：

| # | 禁止项 | 正确的替代做法 |
|---|---|---|
| 1 | **【待核实】/【待确认】/【TBD】标记** | 给出自洽数值并按 §1.2 五拍法自圆其说；不确定性写进**随附清单** |
| 2 | **来源标注**（「来源：××」「据××报道」） | 直接陈述事实，来源不进正文 |
| 3 | **参考文献 / 脚注 / URL** | 研究现状靠**点名学者与机构**承担可信度（主源全文 0 处 URL） |
| 4 | **「公开渠道未见」「未获取」「暂缺」** | 删掉该句，或取证后改写为确定陈述 |
| 5 | **「本文件为草稿」「初稿供讨论」** | 只在交付说明里提示，正文一字不提 |
| 6 | **合规声明 / 保密声明 / 非密声明（混入段落）** | 程序性声明**单独成页或单独栏位** |
| 7 | **形式审查自查表 / 打分自评表 / 打钩清单** | 自检做成**独立文件**，绝不并入正文 |
| 8 | **AI 使用说明（作为正文段落）** | 按制度规定的**位置与格式**放置标识，不写成正文论述 |
| 9 | **写作指令残留**（「此处插入流程图」「（待补图）」） | 直接给出**图号 + 题注** |
| 10 | **元话语**（「本文档」「本申报书旨在……」） | 直接进入内容 |
| 11 | **对冲词堆叠**（「可能」「或许」「有待论证」） | 结论用「实现 / 定为 / 能够」；条件用「在……情况下」 |

**实测证据**：对主源全文做子串计数，「待核实」「来源」「公开渠道」「草稿」「合规」「自查」「形式审查」「http」「www.」「参考文献」「注释」「AI」「版权」**命中数全部为 0**。

### 1.2 铁律 · 正文必须做到（做到即合格）

1. **每条指标 = 一句指标 + 一整段论证。** 论证段固定五拍：「**给出数值 → 说明现有技术水平基线（必须给基线数！主源分别给了 90% / 90%以上 / 95%）→ 说清现有方法为何不够 → 本项目为何能超过（落到机理与特征）→ 因此定为该值。**」
   - 反例（禁止）：指标只写数值无论证；论证里没有基线数值；只写「显著提升」「国内领先」。
2. **敢于写具体。** 具体事件、具体机构、具体学者、具体模型名、具体章节编号。主源研究现状点名了具体学者与机构（如「海军工程大学的顾建农教授」「种劲松等人」「牛蕾等人」「Lord Kelvin」「Fournier 等人」），**且全文无一处 URL**。

2a. **研究现状必须按「技术演进链」写，不是平铺罗列。** 学术类研究现状的写法是循序渐进：某技术最早由谁在哪年提出→解决了什么问题→遗留了什么缺陷→后人如何在其基础上改进→当前最前沿做到什么程度→**仍未解决的问题是什么（这就是本项目的切入点）**。情报类研究现状必须给出具体型号、具体指标、具体事件（如「美国 AN/TPY-2 雷达探测距离大于 1000 km」「2024 年俄乌冲突中 FPV 无人机实战使用频率同比上升 300%」），禁止只写「国外研究了多年」「取得了显著进展」。每个研究方向末尾必须收束到「因此需要……」。

3. **每段必须闭环收束。** 研究现状段末收到「虽……但……仍没有很好的解决方法……因此需要寻找新的算法」；研究内容段末收到「实现……」；在研项目介绍段末收到「……为本项目研究奠定了技术基础」。
4. **研究内容是绝对主体。** 主源正文实测约 **3.75 万字**，其中研究内容章占 **65.1%**（24,445 字 / 310 行）。写作预算：研究内容 **60–70%**、立项依据 12–18%、团队与基础 12–18%、成果与指标 5–8%、摘要 ≤600 字。
5. **每图有编号 + 题注，题注说清「这是什么图」。** 研究内容每个子项**一段 + 紧跟一张图**；编号带章号前缀（如研究内容属第四章 → `图4-1 … 图4-57`）；表格用独立序列 `表1` `表2`，题注在表上方、图的题注在图下方。

### 1.3 铁律 · 元信息剥离（上一版项目书最大的文体事故）

> **正文承担「确定」，随附清单承担「不确定」。二者物理分离，绝不混排。**

| 不确定性 | 正文写成什么 | 写到哪里 |
|---|---|---|
| 数值待定（指标、经费、周期） | 一个**自洽的确定数值** + 五拍论证 | 随附清单：现值 + 须核对对象 |
| 条件待定（测试环境、等级、样本） | 写具体条件 | 随附清单 |
| 材料待补（协议、声明、资质） | **正文完全不提** | 随附清单的待办附件 |
| 事实未取证（标准号、数据、观点） | **取证后直接写；取不到就整句删掉** | 随附清单记录「已删」 |
| 来源标注 | 不写 | 随附清单的出处对照表 |
| 合规/程序状态、AI 声明 | 按制度单独放置 | 随附清单 |
| 自检结论 | 不写 | **独立的自检报告文件** |

**随附清单标准结构**（与正文同批交付，**绝不并入正文**）：`一、需用户确认的数值` / `二、已删去的内容` / `三、待补的附件材料` / `四、事实出处对照` / `五、程序性事项`。

**判定口诀**：一句话里出现「待 / 暂 / 可能不确定 / 不适用但……」，就**拆成两句**——一句写成确定的进正文，一句写成待办的进清单。

### 1.4 铁律 · 结构、格式与篇幅事实（可直接执行）

- **章节编号体系（主源实测，五级）**：`一、` → `（一）` → `1.` → `1.1` → `1.1.1`。**同一份文本内部命名必须自洽**；不同体系不得混用（军工建议书用「一、二、三」；国重研发申报书用「第一部分……第八部分」）。
- **无内容即写「无」**：这是两个体系的共同明文要求（主源「与有关计划关系」下正文就是「无」）。
- **字体字号**：标题**黑体四号**、正文**宋体小四**（来自国重研发申报书《填报说明》原文，为事实）。
- **行距倍数：不可辨识。** 原 PDF 文本层损坏（子集字体缺 ToUnicode），「正文（包括标题）行距为 __ 倍」的数字位为空。**严禁凭经验填 1.5 / 1.25 等数值**；以本单位当年度转发模板的实际排版为准。
- **经费**：**正文只放概算表**（三列：科目名称 / 申请经费 / 备注，单位万元），表下只加一句「本项目申请经费 X 万元，另外自筹经费 Y 万元。」；**测算文字与明细表进附件**（主源为「附件1 项目经费概算说明」）。
- **表格与正文的分工铁律**：表格进正文，测算文字进附件。
- **诚信承诺书是制度文本，不是作文**：条数、措辞、主体（单位/个人）随体系不同，**必须照抄用户当年模板原文**。主源为个人承诺 7 条，其第 3 条即「所申报项目研究内容没有通过其它计划渠道立项支持」（重复申报承诺的正文落点）。

### 1.4a 技术路线图（必须出图，不得以文字代替）

- **总体技术路线图**：研究内容章开头（或紧接研究目标之后）必须有一张总体技术路线图，展示「研究目标 → 各分技术 → 关键技术点 → 预期成果」的逻辑关系。图题注格式：`图X-X 总体技术路线图`。
- **分技术路线图**：每个分技术（研究内容的每个子项）必须配一张该技术的技术路线图，展示该技术内部的「输入 → 处理流程 → 关键算法/模型 → 输出」。
- **图源文件**：全部图源文件（.drawio XML）必须单独保存到 `图源/` 子目录，与 .docx 分开交付，便于用户后期手工调整。
- **生成方式**：AI 生成 draw.io XML → 调用 drawio CLI 导出 PNG → 插入 Word 正文对应位置。CLI 路径：`D:\devtools\drawio\draw.io.exe --export --format png --output <png路径> <drawio路径>`。
- **禁止**：用纯文字描述技术路线而不配图；把路线图做成正文表格；图无编号无题注。

### 1.5 写作前后的强制动作

1. **动笔前**读 `references/09` §1（铁律）与 §3（剥离规则）。
2. **搭骨架时**即在每节标题下写清「本节必须出现的确定信息」清单；缺的信息**当场问用户，不得先写占位符**。
3. **每写完一章**跑一次 §1.1 的 11 条禁止项自查，命中就地改成确定句，不确定性搬进清单。
4. **写完指标章**单独跑一次 §1.2 第 1 条的五拍法检查：**每条指标必须有基线数值**。
5. **交付时**：正文 + 图表清单 + 经费表 + **【随附清单】** + **独立的自检报告** + 出处对照。**正文里不带任何草稿痕迹。**

### 1.6 公式写法规范（`$...$` 与 `$$...$$` → Word 原生 OMML 公式）

研究内容章涉及信号处理、检测理论、物理模型的推导时**必须使用公式**，不得用中文长句描述数学关系——参照件（凌霄）的研究内容章核心论证段落均以公式驱动。配套的 `md2docx.py` 转换器会自动将 LaTeX 数学标记转为 Word 原生 OMML 公式（不是图片、不是 MathType 外挂、不需要用户二次操作）。

**标记规则：**

- **独立行公式**（带编号或不带）：上下各空一行，公式独占一行，用 `$$...$$` 包裹。

  ```markdown
  积累增益为：

  $$
  G = 10\log_{10}(N)
  $$

  其中 $N$ 为积累脉冲数。
  ```

- **行内公式**：用单美元符 `$...$` 包裹。

  ```markdown
  多普勒分辨率 $\Delta f = 1/T$，速度模糊区间 $\Delta v = \lambda f_r / 2$。
  ```

**支持的 LaTeX 命令集（白名单——不在其中的不得使用）：**

| 类别 | 命令 | 写法示例 |
|------|------|----------|
| 分式 | `\frac{a}{b}` | `$$\frac{c}{2B}$$` |
| 根式 | `\sqrt{x}`, `\sqrt[n]{x}` | `$$\sqrt{-2\ln P_{fa}}$$` |
| 上下标 | `^{x}`, `_{x}`, `^{expr}`, `_{expr}` | `$10\log_{10}(N)$`, `$x^2$` |
| 希腊小写 | `\alpha \beta \gamma \delta \epsilon \theta \lambda \mu \pi \sigma \omega \phi` | `$\Delta f$`, `$\sigma^2$` |
| 希腊大写 | `\Delta \Sigma \Pi \Omega \Gamma \Theta \Lambda` | `$\Delta R$`, `$\Sigma$` |
| 运算符 | `\times \cdot \div \pm \mp \leq \geq \approx \neq \propto` | `$2 \times 3$`, `$P_d \geq 0.9$` |
| 函数名 | `\log \ln \sin \cos \tan \exp \max \min \lim` | `$10\log_{10}(N)$`, `$\exp(-x)$` |
| 符号 | `\infty \partial \nabla \rightarrow \Rightarrow` | `$T \rightarrow \infty$` |
| 积分/求和 | `\int_{a}^{b} \sum_{i=1}^{n}` | `$$\int_{T}^{\infty} p(x)dx$$`（注：积分在当前引擎中以行内文本渲染，不建 n-ary 结构） |

**密度要求**：研究内容章的每个分技术至少 3-5 个核心公式（探测方程、门限计算、滤波递推、损失函数等），技术指标论证段的关键计算也应公式化。总量目标 25-35 个公式（独立行 `$$...$$` 与行内 `$...$` 混合）。允许使用 `\hat{}`、`\bar{}`、`\mathrm{}`、`\text{}` 等排版命令——转换器不支持的命令会在生成时自动降级为最接近的 OMML 形式，不会报错中断。用户可后期在 Word 中统一调整公式样式。

**不支持的命令（不得出现在正文中，否则 docx 转换将丢失或乱码）：**
`\hat{x}`, `\bar{x}`, `\tilde{x}`, `\vec{x}`（重音符）；`\mathrm{...}`, `\text{...}`, `\operatorname{...}`（字体切换）；`\begin{cases}`, `\pmatrix{}`, `\bmatrix{}`（矩阵结构）；`\left`, `\right`（自动缩放——会被转换器剥离，普通括号直接用）。

**公式撰写四原则：**

1. **每公式必解释变量**——但必须短（一句），不得写成教科书。
2. **公式必须嵌入论证逻辑链**：先说明为什么需要这个公式（解决什么问题）→ 给出公式 → 再说公式推导出的结论或数值估计。
3. **禁止装饰性公式**：没有推导价值的"公式陈列"是扣分项。每个公式都必须是后续论证的前提。
4. **数值与公式分离**：公式表达数学关系，具体数值代入写在外面：`$$R = \frac{c}{2B}$$` 随后另起一段"取 $B = 20$ MHz，则 $\Delta R = 7.5$ 米。"

**交付时：**
- 正文 `.md` 里的 `$$...$$` 和 `$...$` 由 `md2docx.py` 自动转为 `.docx` 里的原生 Word 公式。
- 如果项目要求提交 `.pdf`，从 `.docx` 导出——不要在 `.md` 里用 LaTeX 渲染引擎直接出 `.pdf`。

## 2. 使用前提（先读这一节，不满足就不要往下走）

本技能产出的**是可直接进入评审的正文文体**——正文里不出现任何草稿痕迹（见 §1）。但**数值、盖章与程序性事项仍须由用户核实确认**，并以**随附清单**（见 §1.3）的形式与正文同批交付，**不并入正文**。原因见 §4。

开工前必须向用户索取以下四项，缺一项就会写出无效文本：

| # | 必须提供 | 用途 |
|---|---|---|
| 1 | **当年度指南原文（脱密后）** —— 指南条目编号、名称、研究目标、技术指标、进度、成果形式、经费限额、拟支持数量 | 决定选题对齐与指标上限。**拟支持数量直接决定风险**：只支持 1 项时，会评名额只有 2 席 |
| 2 | **本单位科研处/科研院转发的模板原件** | 决定章节骨架、字体字号、经费科目表头、盖章栏位。**模板优先于一切经验** |
| 3 | **负责人资格与限项情况** | 年龄/职称门槛、在研项目超项、同年度同类项目申报数限制 |
| 4 | **截止时间与校内截止时间** | 校内通常比正式截止提前，用于科研处做形式审查 |

**如果用户没有指南原文**，必须当面说明：本技能**无法替代指南约束**，只能辅助结构与论证质量；产出的措辞、指标、经费都要由用户对着指南逐条替换。

**但正文不因此写占位符。** 按 §1.3，正文给出**自洽的确定数值**并按 §1.2 五拍法写足论证，同时把「该现值须与指南条目 X 的指标上限核对」写入**随附清单**。**禁止在正文里写【待核实】或"以指南为准"。**

另需先确认两件事：**本项目走公开渠道还是涉密渠道**（见 §2），**文本类型是 A 卷还是 B 卷**（见 §4）。

## 3. 合规红线（前置检查，不是附录）

以下四条中任意一条被违反，文本**在进入技术评审之前就已经出局**，写得再好也没用。

1. **涉密指南不得经互联网传播。** 涉密指南只能通过**组织渠道**查询（173 计划的官方表述即"涉密指南可通过组织渠道查询"）。**禁止**：把涉密指南内容上传到联网 AI 工具、网盘、公网邮箱；用联网检索工具去查、去猜、去拼凑涉密条目内容。本技能的工作方式**始终是**"公开信息 + 用户提供的脱密材料"，涉密部分只在单位保密场所、按保密要求由人处理。
2. **盲评版必须去单位与申请人身份化。** 装备预研共用技术盲评打分表明确规定：申请书内容**泄露单位或申报人信息，计分为 0**；评审方核实后**按盲评不通过处理**。这不是"隐藏一下"，而是**整篇文本的写作约束** —— 见 §6 第 4 条执行清单。
3. **公开项目必须出具盖章的《非密声明》。** 快速支持机制明确要求：公开项目建议**必须随附加盖公章的《非密声明》**，严禁填写涉密、敏感信息。其他体系以本单位通知为准。
4. **涉密项目须有与密级相应的保密资质。** 公开发布的非密指南条目**不要求**保密资质；**涉密指南条目须有相应保密资质**。注意：军工保密资质已于 2025-07-01 起改为**一级、二级两等制**，引用旧公告中"三级以上/二级以上"表述时必须核对当年有效制度。
    - "**两证**"是业内口语，分别指 ①"武器装备科研生产许可 + 军工保密资质"，或 ②"武器装备质量管理体系认证 + 装备承制单位资格审查（2017-10-01 起"两证合一"，只发一个证书）"。**用到这个词时必须同句写明所指组合**，否则资质名称会写错。

> 参考：`references/05-评审与合规避坑.md` §4 保密与合规、§5.5 军工资质。

## 4. 能力边界（不得越界承诺）

以下边界**必须向用户明确说明**——但注意：**「能力边界」是对话内容，不是正文内容。** 按 §1.1，这些话**一律不得写进申报正文**，只写在交付说明与随附清单里。

1. **173 计划技术领域基金、装备预研共用技术、快速支持、军科委/国防科技创新快速响应小组的指南正文与部分模板正文，公开渠道未获取。** 素材库只到手到"附件名称"或转发通知层级；173 的《指南/研究方向》唯一到手件是**扫描图片版**（文本抽取仅 63 字符）。**本技能不得假装知道这些计划的具体评分细则、条目内容或内部规则。**
2. 对上述计划，本技能的定位是**"结构与论证质量辅助"**，并**必须**要求用户提供脱密后的指南原文与目标模板。
3. **本技能承诺的是「可直接进入评审的正文文体」，不承诺通过率。** 正文本身**不带任何草稿痕迹**（§1）；需要用户落实的是**数值核实、盖章、程序性材料**，这些都走**随附清单**（§1.3），**不在正文里留痕**。
4. 已完成的研究只能提供**公开渠道的"某版规范"数值**，且**必须带版本警示**（见 §7）。

## 5. AI 使用规则（必须向用户原文交代）

**国家自然科学基金 2026 年度申请通告**的原文要求：

> "申请人在撰写申请书时，如果借助生成式人工智能技术跟踪研究动态、收集整理参考文献，**必须由人工核实**生成式人工智能生成信息和参考文献的真实性和准确性。申请人应当对使用的生成内容负责，应当**全面如实声明使用情况**，按照《人工智能生成合成内容标识办法》《负责任研究行为规范指引（2023）》等国家有关规定**对相关内容进行标识**……**不得使用由生成式人工智能直接生成的申请书，不得使用未经核实的生成内容。**"

（[通告原文](https://www.nsfc.gov.cn/p1/3381/2824/99667.html)；解读见 `references/05-评审与合规避坑.md` §6.5）

**因此本技能输出的一律是「草稿」，并要求用户：**

- **逐句人工核实**所有事实、数据、文献、指标、标准号；
- 在正式文本中**如实声明** AI 使用情况，并按《人工智能生成合成内容标识办法》在文本起始/末尾合适位置添加**标识**；
- **军口/国防科工局渠道公开渠道未见同等明文要求**，故按"**更严者为准**"处理：先向本单位科研院/保密办确认口径；**AI 工具本身不得接触任何涉密或敏感内容**。

**技能自身的动作约束**：AI 不得独自决定技术指标、经费数字、资质表述、评审规则；这些只能来自用户提供的指南与模板，或由用户确认。

**与文体的接口**：AI 使用声明与标识**按制度规定的位次与格式放置，不写成正文里的一段论述**（§1.1 第 8 条）。

## 6. 第一步：分支判断（拿到材料先做这四问）

四条分界线各自**独立**决定后续用什么骨架、什么论述重心。判断结果写成一行，贴在文档顶部。

| # | 问题 | 取值 | 它决定什么 |
|---|---|---|---|
| 1 | **文本类型** | 项目建议书 / 立项论证 **vs** 正式申报书 / 任务书 | **骨架 A vs 骨架 B**（见 §7 第 1 步） |
| 2 | **制度类型** | **基金制** vs **合同制** | 是否需要审价、是否设中间考核节点、经费表的编制逻辑。例：快速扶持＝基金制（**不组织审价、不设中间考核节点**）；快速转化＝合同制（**可设一个中间考核节点**）。**写反即暴露不了解机制** |
| 3 | **终点** | **择优立项** vs **签订合同/任务书** | 文本的"承诺强度"。终点是签合同的（如快速转化），指标与考核方式须写成可验收条款 |
| 4 | **指南密级** | **公开指南** vs **涉密指南** | 走哪条申报路径、要不要《非密声明》、要不要保密资质、模板取涉密版还是公开版 |

**补充判断（影响工作量）**：本项目属于哪个计划？——**173 基金 / 基础加强 / 快速扶持 / 快速转化 / 快响小组 / 国防科工局基础科研 / 国防科工局技术基础科研 / 国家重点研发计划 / 国自然**。计划决定主管单位、文本名称、评审方式与经费科目口径（对照表见 `references/01-申报体系总览.md` §对照表）。

**关键判据：看模板的表头和栏目，不要先看经验。** 尤其是经费科目——**装发部口径 10 项（材料费/专用费/外协费/燃料动力费/事务费/固定资产折旧费/管理费/工资及劳务费/收益/不可预见费）；173 口径为"直接费用 9 项 + 间接费用"**。两套**互不兼容**，套错直接是形式审查问题。

## 7. 写作工作流（六步，逐步产出）

### 第 1 步 · 选骨架
> **动笔前先读 §1（文体与格式铁律）与 references/09。** 骨架解决「写哪些章」，§1 解决「写成什么样」。
- 判断结果＝**建议书/立项论证** → 读 `references/02-骨架A-项目建议书与立项论证.md`（含 173 官方模板七个一级标题、快速支持三套模板结构差异）。
- 判断结果＝**正式申报书/任务书** → 读 `references/03-骨架B-正式申报书与任务书.md`（16 章逐章"必备要素清单 / 可套用写法 / 常见错误"）。
- **产出**：一份带章节标题的空骨架，标注每章目标字数占比。**先搭骨架后写正文**，不要边想边写。

### 第 2 步 · 逐章写作
按 `references/04-写作要点与经验.md`（怎么写：立项依据、创新点、技术路线图、指标、经费、团队）与 02/03 的"③ 可直接套用的写法"逐章填。

- **立项依据**：落到"这条指南条目为什么非做不可"，不是行业趋势综述。国防科工局技术基础体系明文要求"必要性"栏**须阐明拟解决的重大问题**。
- **研究目标**：军味句式（可直接照搬快速转化模板提示语）——"研究背景或需求（**需明确具体的型号、背景等，写具体**），突破××技术，研制出××成果，通过××考核，达到××状态或指标，具备××能力，取得××效果，**预期达到的技术成熟度等级**。"
- **创新点**：写成**可指认的新增量**（原理新 / 方法新 / 指标新），要有对照组；不要写"首次提出"却无依据，用"在……范围内未见公开报道"更稳。
- **研究基础**：只写与**本项目关键技术直接相关**的前期成果，不堆论文数量。
- **产出**：各章草稿。**每章不再标注【待核实】项**（§1.1 第 1 条）。取而代之：① 正文该确定的地方**给出自洽的确定值并写足论证**；② 该值需与指南核对的，**记入随附清单**（§1.3）。
- **本步的定量要求**：按 §1.2 第 4 条分配篇幅，**研究内容占正文 60–70%**。

### 第 3 步 · 技术指标可考核化（最容易被扣分的一步）
把每条指标改写成"**可测量 + 有基线 + 有测试条件 + 有判定准则 + 有考核方式 + 有验证节点**"。
快速转化模板明确要求考核方式写清**考核实施单位（具备相关测试评价资质的第三方、武器装备研制总体单位或承研方自测）、考核环境、考核方法、考核依据（标准）、考核指标**。指标表列结构见 `references/03` §7。

**要求用户确认**：验收佐证的形态。公开渠道可查的军工口做法是须 CMA/CNAS 第三方检测报告或**三家以上应用单位用户报告**，且**须覆盖所有考核技术指标**。

- **禁止**：只写"显著提升""达到国内领先""填补空白"而无基线、无单位、无测试条件。
- **产出**：**编号指标句 + 每条一整段五拍论证**（§1.2 第 1 条）。评估方案另出一张三列表（序号 / 具体成果名称 / 考核方式），考核方式用固定词「会议评审 / 审查 / 测试、试验验证」。
- **每条指标必须给出基线数值**——没有基线就无法说明「为什么定这个值」。基线取不到时，**该指标整条重写或删除**，不得留空、不得标注待核实。

### 第 4 步 · 经费按计划选对科目表
1. **先看模板表头**，确认是装发部 10 项口径还是 173 的"直接费用 9 项 + 间接费用"口径。
2. 按研究内容分解 + 按年度分解（快速转化模板的两条分解线）。
3. 做**三向勾稽自检**：子项之和＝总经费；各单位之和＝项目总经费；管理费 ≤ 总经费 × 8%（国防科工局类项目硬红线）。
4. 对照 §1 与 `references/00-评分与合规速查.md` §3 的签署栏要求。

- 173 特有条款：**项目参研单位不能作为外协单位承担任务**；而快速转化模板**明确要求写"外协条件"**——两处**不可对调**。
- **产出**：**正文概算表**（科目名称 / 申请经费 / 备注，单位万元，表下只加一句「申请 X 万元，自筹 Y 万元」）+ **附件《项目经费概算说明》**（每科目测算依据与明细表）+ 勾稽表。**测算文字不进正文**（§1.4）。

### 第 5 步 · 合规自检（不通过不许交付）
1. 跑 `references/05-评审与合规避坑.md` §3 **形式审查雷区清单（14 条）**，逐条打钩。
2. 跑 `references/02` / `03` 各章"④ 常见错误与扣分点"，以及本文件 §6 清单。
3. **盲评版专项去身份化核对**（逐项确认，见 §6 第 4 条）。
4. **AI 使用声明与标识**已按 §3 落实。
5. **产出**：自检表（哪条通过 / 哪条存疑 / 哪条未核实）。**自检表是独立文件，绝不并入正文**（§1.1 第 7 条）。
6. **文体自检（新增，必跑）**：跑一次 §1.1 的 11 条禁止项，逐条确认正文里为 0 命中。任一条命中即回改。

### 第 6 步 · 交付
交付物应包含：**正文**（不带任何草稿痕迹，见 §1.1）、指标表、经费表与勾稽表、**独立的自检报告**、**【随附清单】**（结构见 §1.3：需用户确认的数值 / 已删去的内容 / 待补的附件材料 / 事实出处对照 / 程序性事项）、**AI 使用声明与标识文本**（按制度位次放置，**不进正文**）、用到的指南条目与模板的出处对照。

- **交付时必须再次口头提醒**：正文已按「真件文体」写成，**但其中的数值、事实、资质与盖章事项仍须由申请人逐句核实、署名并承担内容责任**；核实项见随附清单。**不要把「这是草稿」写进正文。**
- **产出**：交付说明 + **随附清单**。

## 8. 评分导向：分从哪里来（决定了篇幅怎么分配）

**已验证的权重事实（装备预研共用技术）**：

| | 盲评（满分 90） | 会评（满分 100） |
|---|---|---|
| 研究目标和技术指标 | 10 | 10 |
| **研究方案及技术途径** | **30** | **30** |
| **创新性** | **30** | 25 |
| 成果及其考核方式 | 10 | 20 |
| 军事应用前景 | 10 | —（换为"研究基础和保障条件 15"） |
| **研究与创新合计** | **60 / 90 ＝ 2/3** | **55 / 100** |

**据此的写作优先级（可执行）**（与 §1.2 第 4 条的篇幅配比配合使用：**两套体系都以「研究方案/研究内容」为主体**，结论一致，可放心照此分配）：

1. **把主要篇幅给"研究方案及技术途径"和"创新性"。** 盲评这两项占 2/3；**不要把篇幅堆在研究基础上**——盲评 5 个评价项里**根本没有"研究基础"**，研究基础只在会评出现（15 分）。
2. **"研究目标和技术指标"只占 10 分，但选错方向是 0 分。** 所以**先花时间选定并逐字对齐指南条目**（研究目标/指标/进度/成果形式/经费限额须全部满足），再动笔。
3. **"成果及其考核方式"会评权重翻倍（10→20）**：会评评委更看"交付与验收"。里程碑、交付物、验收标准要在会评版里写足。
4. **盲评版必须去身份化（两类 0 分之一，见 §3 第 2 条）**，逐项核对：
   - 删除/替换单位名称、简称、Logo、地址、邮编、机要地址；
   - 删除申请人及团队姓名、职称组合、联系方式、身份证号；
   - 检查**间接线索**：邮箱域名、单位内部项目编号、试验平台/样机的独特名称、自引文献的写法（"我们前期在《××》发表的……"）、致谢、落款、文档属性（作者/单位元数据）、页眉页脚；
   - 检查**图表的坐标标签与照片**是否含单位标识；
   - 检查文件名与命名规范（快速支持要求"负责人-X.X技术方向-项目建议书（第N阶段）"——该命名本身含负责人姓名，**仅用于线上提交，不得出现在盲评正文中**）。
5. **"非申请人汇报扣 5 分"**：如需换人汇报必须**提前书面申请并获批**；把这件事在交付说明里提醒。
6. **会评通过是复合条件（≥60 分 且 与第一名差 ≤20 分 且 排名在拟支持数量内）**：同条目竞争强度决定成败，建议用户在选题阶段就查清**该条目的拟支持数量**。

详尽数字与来源见 `references/00-评分与合规速查.md`。

> **⚠️ 版本漂移**：以上数值来自已获取的打分表原件与所引版本规范。**不得把任何一年的分数线、加减分、权重当作通例**（例：民营企业加分在 2017 版为 +5，在 2018/2021 版所引条文为 +3）。**必须带"以当年指南与当版工作规范为准"的提示。**

## 9. 常见致命错误清单（逐条可执行）

> 前加 `[盲评0分]` / `[形式审查]` 的为**一票否决**类，优先检查。

1. **`[形式审查]` 拿不到模板就按"通用结构"动笔。** → 没有本单位转发模板就先停下索取，模板决定章节、字体字号、科目表头。**行距倍数等不可辨识的格式数值，一律不得凭经验填写**（§1.4）。
2. **`[盲评0分]` 盲评版残留单位/申请人信息。** → 按 §6 第 4 条清单逐项删除，含元数据、图表标签、自引写法。
3. **`[盲评0分]` 研究方向不在指南条目的技术领域内。** → 逐字比对指南条目编号与名称，宁可换条目。
4. **`[形式审查]` 经费科目口径用错。** → 装发部 10 项 vs 173"直接费用 9 项+间接费用"，**先看模板表头再填数**。
5. **`[形式审查]` 管理费超过项目成本总额 8%（国防科工局类）。** → 算一遍，并同时核对子项之和＝总经费、各单位之和＝总经费。
6. **`[形式审查]` 该签名盖章的栏位空着。** → 经费匡算栏财务主管领导签名、诚信承诺栏主要领导签名＋公章、主管部门意见栏公章，逐栏确认。
7. **`[形式审查]` 项目名称/承研单位/周期/负责人/经费/密级与项目汇总表不一致。** → 做一张两列对照表逐项核。
8. **指标写"显著提升""国内领先""填补空白"而无基线、单位、测试条件。** → 按 §1.2 第 1 条的五拍法改写：**数值 → 现有技术基线数值 → 现有方法为何不够 → 本项目为何能超过 → 因此定为该值**，并补全单位、测试条件与判定准则。
9. **把论文/专利数量当作主要成果形式。** → 军口体系**公开论文往往不是被期待的成果形式**，甚至触发保密审查；成果形式须与指南条目要求一致。
10. **"论文/论文署名"与项目保密边界不清。** → 参研人员的公开发表须走本单位保密审查，不在项目书里承诺"发表 SCI 若干篇"（除非指南明确要求）。
11. **中间考核节点写反。** → 快速扶持**不设**中间考核节点；快速转化**可设一个**。
12. **外协口径写反。** → 173"参研单位不能作为外协单位"；快速转化要求写"外协条件"。两处不可对调。
13. **创新点三条其实是同一条，或没有对照组。** → 每条创新点必须能指认"新增量"并与现有方案比较。
14. **重复申报未自查。** → 检查同一研究内容是否已在其他计划渠道申报/立项，并在承诺栏如实声明；173 模板含"相关研究内容没有在其它计划渠道重复申报"承诺。
15. **AI 生成内容未核实、未声明、未标识。** → 按 §3 落实；**不得提交未经人工核实的生成内容**。
16. **引用标准号未确证。** → 引用 GJB 等标准前必须核到标准号与名称；素材库对部分标准**刻意不作内容性引用**。
17. **`[文体一票否决]` 正文里混入元信息。** → 正文出现【待核实】标记、来源标注、URL/参考文献、"本文件为草稿"、合规声明、形式审查自查表、"此处插入图"、AI 使用段落中的**任意一项**，即视为不合格。逐条跑 §1.1 的 11 条，改为确定句，不确定性搬入随附清单（§1.3）。

（更完整的形式审查 14 条雷区见 `references/05` §3；各章扣分点见 `references/02`/`03` 各章"④"。）
